## a6-01 (material, security) — the write surface is closed

**Changed.** New `apps/api/src/adminAuth.guard.ts` (`AdminWriteGuard`, `ADMIN_TOKEN`, `MIN_ADMIN_TOKEN_LENGTH = 16`, `bearerMatches`, `isJsonContentType`); `app.module.ts` (`adminTokenFromEnvironment`, the `ADMIN_TOKEN` provider, the guard registered under `APP_GUARD` so no route can be added without it); `main.ts` (`OTC_BIND`, default `127.0.0.1`, `app.listen(port, host)`; the CORS comment rewritten; the boot line says whether writes are enabled); `apps/web/src/app/engine/[...path]/route.ts` (adds `Authorization: Bearer <OTC_ADMIN_TOKEN>` from its own environment to every non-`GET`/`HEAD` request, per request like the address; never forwards a browser's `authorization`; never returns it); `apps/web/src/lib/api.ts` (every write, retire included, is `application/json` with a JSON body); every service-booting test passes the token and the content type.

**Rules.** (a) `GET`/`HEAD`/`OPTIONS` pass; everything else needs `Authorization: Bearer <token>`, compared as `timingSafeEqual` over SHA-256 digests of both sides (equal lengths, so the token's length is not a timing signal). (b) With `OTC_ADMIN_TOKEN` unset the service boots, reads are unaffected, and every write is `403` with a message naming the variable. (c) Every write must be `Content-Type: application/json` (parameters ignored), else `415` — so no write is a CORS simple request. The token is checked before the media type, deliberately: a caller without the credential learns nothing about a well-formed write.

**Before** (audit, `curl -si -X POST /assets/gbpjpy/retire -H 'Origin: http://evil.example'`): `HTTP/1.1 201 Created … {"id":"gbpjpy","retiredAt":…}`, `ss -ltnp` → `*:34107`.

**After** — `registration.stat.test.ts › closes the write surface to anything but the operator, whatever the origin (a6-01)`, against the spawned service with `Origin: http://evil.example` on every request:

```
POST /assets/gbpjpy/retire  (no body, no header)                     → 403  "This write needs "Authorization: Bearer <OTC_ADMIN_TOKEN>" …"
POST … authorization: Bearer not-the-operator-token-at-all + JSON    → 403
POST … Bearer <token>, content-type: text/plain, body '{}'           → 415
GET  /catalogue (still live: true for gbpjpy)                        → 200
POST … Bearer <token>, application/json, body '{}'                   → 201
GET  /catalogue from evil.example                                    → 200
```

and `› boots without a token with every write refused by name …`: `PATCH /assets/eurusd` with the token and JSON on a service started **without** `OTC_ADMIN_TOKEN` → `403 "Writes are refused on this engine because OTC_ADMIN_TOKEN is not set. …"`, `GET /markets` → 200; a boot with `OTC_ADMIN_TOKEN=short` exits non-zero with `OTC_ADMIN_TOKEN is 5 characters; it must be at least 16`. Bind: `main.ts` logs `hosting 5 markets on 127.0.0.1:<port>; writes need the bearer token`.

**Watched failing.** Plant `provide: APP_GUARD` → `provide: 'NOT_THE_APP_GUARD'` (guard still a provider, not global), rebuilt, `registration.stat.test.ts -t "closes the write surface"`: `× … → the simple request a page can send: expected 201 to be 403`, exit 1; restored (digest verified), rebuilt, passes. Proxy plant (token added only when absent): `engineProxy.test.ts -t "operator token"` → `expected null to be 'Bearer operator-token-of-thirty-two-c…'`, exit 1; restored. Eight guard unit tests in `adminSurface.test.ts` (`the write surface needs the operator token (a6-01)`) cover reads, unset token, wrong/missing/other-scheme bearer, non-JSON after the credential, JSON with parameters, `canActivate` on a request object, digest comparison, and the boot rule.

**Decisions and alternatives.**

- **403 for a missing or wrong token, as the orchestrator decided**, not 401: there is no realm to challenge into and the message is what an operator reads; the panel adds the credential on its server so a browser never sees the response as a login.
- **A minimum token length of 16, refused at boot** (my addition): a guessable token is not a credential, and refusing loudly before anything is hosted is the discipline `OTC_MASTER_SECRET must be 64 hex characters` already sets. Unset stays allowed, per the brief.
- **The token is injected, not read in the guard.** `apps/api/src` is inside the guardrail scan's replayable roots and `process.env` is refused everywhere but `app.module.ts`, `main.ts`, `publication.service.ts` (`AMBIENT_STATE_ALLOWLIST`). The composition root reads it once and provides it under `ADMIN_TOKEN`. Same for the boot nonce (a6-14). `crypto` as a bare identifier is also refused by the scan; only the two named imports are used.
- **Bind default `127.0.0.1`.** `OTC_BIND=0.0.0.0` exposes it, and an operator who does so must set `OTC_ADMIN_TOKEN` first. Alternative — keep every interface and rely on the token — rejected: loopback is the right default for a service whose panel proxies it, and the token is defence against the panel's own origin, not a reason to listen on a LAN.
- **CORS unchanged in behaviour, corrected in words**: the wildcard default still answers a preflight with `GET, HEAD`; a named `OTC_CORS_ORIGIN` still gets `POST, PATCH` — and now still needs the token. `cors` reflects `Access-Control-Request-Headers` when `allowedHeaders` is unset, so `Authorization` passes a named origin's preflight.
- Alternative for the browser — a session cookie — rejected: the panel already proxies under one origin, so a server-held bearer is the smallest thing that keeps the browser token-free.

## a6-09 — one shutdown path, exit 0, history closed, streams told

**Changed.** `main.ts`: the `process.once` handlers are gone; `NestFactory.create(…, { forceCloseConnections: true })`; `app.enableShutdownHooks(['SIGINT','SIGTERM'], { useProcessExit: true })`. `history.service.ts`: `HistoryService implements OnApplicationShutdown` — closes the store if it has `close()`. `market.controller.ts`: every live stream subscription is tracked; `beforeApplicationShutdown` cancels each with `'server shutting down'` (the sink writes `event: close` and ends the response) and yields one `setImmediate` so the frames reach the sockets before the listener's close destroys them.

**Why `onApplicationShutdown` and not `onModuleDestroy` for the close** (the brief named the latter): Nest runs every `onModuleDestroy` of a module concurrently (`Promise.all` in `hooks/on-module-destroy.hook.js`), so a close there would race `VenueService.onModuleDestroy` — the final checkpoint and the flush that writes the last closed bars _through the store_. The order Nest guarantees is `onModuleDestroy` → `beforeApplicationShutdown` → `dispose()` (listener) → `onApplicationShutdown` → `process.exit(0)`, which is exactly the order shutdown needs; it is one path either way. `forceCloseConnections` is what keeps the listener step finite: `server.close()` waits for active connections and a live market's clients are all active.

**Before** (audit): `exit code null sig SIGTERM after 11 ms`, checkpoint files rewritten twice from one pid, `history.db-wal 3,605,032 B` left. **After** — `restart.stat.test.ts › shuts down once on SIGTERM, exits 0, closes the history, and tells its stream clients` (9.6 s): with an SSE client connected, `SIGTERM` → `{ code: 0, signal: null }`; the client received `event: close` / `server shutting down`; stdout contains `candle history closed` and matches neither `ENOENT` nor `ERROR`; `history.db` exists and `history.db-wal` does not. **Watched failing:** plant `this.history.close()` → `void this.history` (log line kept), rebuilt: `→ promise resolved "undefined" instead of rejecting` on the WAL assertion, exit 1; restored, rebuilt, passes. ## a6-11 / a6-18 — reconnect honestly, and see the venue's health

**`marketStream.ts`** (ticks page): a stream error after the connection had opened reconnects with `window.resumeFrom` (exact continuation, the window's design); an error **before** it opened, with a resume point, is a refusal — evicted, unknown, gone — so the window is replaced with a fresh one, the caller gets `{ kind: 'gap', reason }`, and the next attempt carries no resume point. Backoff `1 s × 2^(n−1)` capped at 30 s, reset on open. `EventSource` is injectable, so the policy is unit-tested in Node (`marketStream.test.ts`, 5 tests): exact resume with `?from=3`; refusal → `gap` → third URL without `?from` → fresh window (`{ oldest: 900, newest: 900 }`); delays `[100, 200, 350, 350, 350]` with `backoffMs: 100, maxBackoffMs: 350`; `close()` stops retries; a non-contiguous batch still throws. `Chart.tsx` shows `live`, `stream interrupted — reconnecting in Ns (attempt n, resuming exactly)`, `gap — …; starting over from now`, `live — reconnected after a gap; the window restarted` (`data-testid="tick-stream-status"`). **Watched failing:** plant "never drop the resume point" → `expected '' to be '?from=12'`, exit 1; restored.

**`PreviewChart.tsx`**: the browser's own `EventSource` retry is no longer relied on. On `onerror` the stream is closed and `run()` is re-run after backoff — **history refetched, builder rebuilt at the new join, a new stream from now** — with status `stream interrupted — reconnecting in Ns (attempt n)`, then `live — reconnected after a gap`; a history fetch that fails during a reconnect is retried the same way. **Stall:** a timer of `STALL_MULTIPLE (3) × asset.meanIntervalMs` is re-armed on every tick; when it fires the status becomes `no tick for Ns — 3× this market's mean interval; check the engine's health`, and the next tick sets `live` again. The status colour keys on `startsWith('live')`.

**`Nav.tsx` / `layout.tsx`**: the shell polls `/health` every `HEALTH_POLL_MS = 5_000` (`fetchHealth` in `api.ts`) and renders `data-testid="health-status"`: `engine ok · 5 hosted`, `engine degraded · 2 of 5 stalled` followed by each `assetId: reason` in the venue's words, or `engine unreachable` with the message. `layout.tsx` passes `API_BASE` to `Nav`.

Note for the browser suite: after a reconnect the status text is `live — reconnected after a gap`, and the suite's `toBe('live')` polls apply to fresh mounts only, so they are unaffected.
