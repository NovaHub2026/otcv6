## 1. Objective

A broker's operator has a state directory now holding checkpoints, a candle
history, a tick record, an asset registry and — when publication is on — a
commitment chain. This subphase makes that directory something an operator can
check, copy and put back, and closes the one open Issue about its files.

## 2. What is built

1. **Integrity at boot.** A `state:check`-shaped verification of the state
   directory before any market resumes: every checkpoint parses and is usable
   (`assertUsableRecord`), the record's head per asset is not behind the
   checkpoint's `lastPublished`, the candle history's stored head is not ahead
   of the record, and the three SQLite files open at a schema this code
   understands. A disagreement refuses the boot by name — the same policy as
   `CorruptRecordError` — rather than seaming past it.
2. **Backup and restore.** A documented, tested procedure: `sqlite3 .backup`
   is not required; the venue exposes `POST /admin/backup` (admin credential)
   that writes a consistent snapshot of the directory — checkpoints copied
   atomically, each SQLite file through `VACUUM INTO` — to a target path, and
   a restore is a directory swap with the service stopped, verified by the
   boot check. Asserted: a venue restored from a backup taken mid-run resumes,
   its record's head equals the backup's, and a client's resume from before the
   backup is honoured.
3. **The commitments file (Issue #19).** `readCommitments` takes the whole
   file as one string; after about six years the chain becomes unverifiable.
   Read it in a streaming, line-bounded way, and rotate the file per window
   count so no single file grows without bound; verification of an old chain
   stays possible.

## 3. Acceptance criteria

1. A corrupted checkpoint, a record behind its checkpoint, a history ahead of
   the record, and a newer schema each refuse the boot with the file and the
   asset named; a healthy directory boots.
2. A backup taken while the venue ticks restores to a venue that resumes
   without a seam and honours a pre-backup resume sequence.
3. A commitment chain of a size that would exhaust a single string is read
   and verified; Issue #19 closed with the number.
4. Every guard watched failing.
