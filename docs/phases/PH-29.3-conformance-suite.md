## 1. Objective

Let a broker check its own deployment the way this repository checks a spawned
one: one command against a live venue, every contracted route exercised, the
stream's resume and gap semantics, the price rule against the stream, a proof
verified against the publisher's key, one report and an exit code.

## 2. What is built

**`@otc/client`** (`packages/client`) — the package a broker embeds, opened
here with what conformance needs and finished in PH-29.4: the contract moves
into it (`apps/api` imports it back, so the venue and its clients share one
definition), the shape checker with it, and `conformance(baseUrl)` — a pure
function over `fetch` that returns a report: per check, pass or fail with the
reason; overall, the venue's version against the client's.

**The checks.** `/health` answers and its `apiVersion` is the client's;
`/contract`'s digest is the client's; every contracted JSON route answers with
exactly the contracted keys and types (the same walk as `contract.test.ts`,
over HTTP); the stream delivers strictly increasing sequences, a resume from
`M+1` continues exactly, a resume from `0` with `onGap=live` is told a gap that
names `resumesAt` and is followed by the retained window; `price?at=` equals
the last tick at or before the instant over the ticks the stream delivered, for
a hundred instants; a proof for a committed sequence verifies with
`verifyInclusion` and `verifyCommitment` against `/health`'s publisher key —
or the venue says it does not publish, which is a pass with a note.

**`npm run conformance -- --base URL [--out report.md]`** in `tools/sim`:
runs it, writes the report, exit 0 when every check passes, 1 otherwise, 2 on
a usage error.

## 3. Acceptance criteria

1. Against a spawned production venue with a record and publication on, every
   check passes and the report says so; the exit is 0.
2. Against a venue whose contract version differs, or whose `/markets/:id`
   carries an uncontracted key, the report names the check and the exit is 1.
3. The suite reaches nothing but the public surface (no engine, no runtime
   import; the lab's boundary scan applied to `packages/client`).
4. Every guard watched failing.

## 5. What the subphase found

1. **Three guards said where a new package must be declared** — the dependency
   policy, the replayable scan roots and the coverage floors — and the layout
   block in `CLAUDE.md`; each refused the package by name until it was.
2. **A client needs its own SSE parser.** The lab's is the same code and the
   lab cannot be shipped to a broker; the reader is written from the
   specification again and tested against a server that splits frames mid-line.
3. **Each check is proved to fail for its reason**: a fake venue with one fault
   at a time — another version, an extra key, a skipped sequence, the wrong
   price rule, a proof that does not verify — fails exactly the named check.
4. **The first run against the shipped service found a wrong refusal**: a
   market that publishes but has closed no window yet answered `404 does not
publish` to a proof request, where the contract says `409 not yet
committed`. The archive's reader now tells a registered asset's directory
   from an absent one; the suite passed the check either way because both are
   listed refusals — which is why the detail column is in the report.
