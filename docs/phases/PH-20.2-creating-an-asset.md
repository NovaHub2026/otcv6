## 1. What existed, and what did not

PH-17 made an asset a registration rather than a compiled constant, and then the
service went on booting `ASSET_CATALOGUE`. Nothing persisted a registration,
nothing could host one, and the panel had no way to ask for one. The pipeline was
real and unreachable.

Five pieces close that, and the order between them is the design:

| Piece                                  | What it decides                                      |
| -------------------------------------- | ---------------------------------------------------- |
| `packages/engine/src/brief.ts`         | what an operator supplies, and what is drawn instead |
| `packages/runtime/src/registry.ts`     | that what was solved is what is stored, verbatim     |
| `Venue.host` / `VenueService.host`     | that a market can join a running venue               |
| `apps/api/src/registration.service.ts` | that creating is a job, one at a time                |
| `apps/web/src/app/assets/new`          | that a refusal reaches the operator in its own words |

## 2. A brief is five fields, and none of them points anywhere

A `RegistrationRequest` carries a twelve-number personality. Nobody types those,
and nobody should: an archetype is a _region_, and twenty hand-authored
near-identical markets are one market with twenty names, which is INV-007 false
as written. So the form asks for an id, a name, a family, a reference price and —
optionally — a **quarterly dispersion budget**, and the personality is drawn from
the family under a stream derived from the asset's own registration label. The
same brief against the same keyring draws the same market, on another machine, a
year later.

The one quantity that describes movement is dispersion: how far, never which way.
The process is a martingale (ADR-0003), so there is nothing for a direction to
attach to — and `brief.test.ts` asserts the field list as a **closed set**,
because a brief that quietly grew a `drift` would be INV-006 broken by an
administrative form.

A supplied budget rescales amplitude and leaves shape alone. The calibration is
homogeneous of degree one in `volatility`, so it is a multiplication, and the
ladder of timescales that makes an asset distinct from its siblings is untouched.

## 3. Storing what was solved

The registry writes the whole `RegisteredAsset` as JSON and reads it back
verbatim. It never re-derives. Recomputing at boot would mean the market a
restart hosts is whatever the current code happens to solve for, and a settlement
recorded last month would be re-derived against a different quantum — INV-009,
broken by a deploy.

It refuses to overwrite, refuses a stored instrument the core rejects, refuses
one whose instrument and definition disagree about the id, and refuses four bytes
of `null` — the malformed shape that parses cleanly, which cost PH-5 a market
restarted at genesis.

## 4. A job, not an insert — and the measurement that corrected the docstring

The first version of this document said a registration is "of order a minute",
copied from the architecture document. It was measured instead:

| archetype       | time  | fit span |
| --------------- | ----- | -------- |
| major-fx        | 3.4s  | 587 h    |
| cross-fx        | 1.6s  | 158 h    |
| blue-chip-index | 2.2s  | 705 h    |
| sector-etf      | 1.4s  | 379 h    |
| metal           | 0.5s  | 61 h     |
| energy          | 0.7s  | 47 h     |
| major-crypto    | 19.3s | 625 h    |
| alt-crypto      | 2.1s  | 59 h     |

Two replicates of `minimumDispersionSpanMs`. **0.5s to 19.3s**, a factor of forty
between families — which is the actual argument for a job: not that a minute is
too long for a request, but that the duration depends on which family the
operator picked, on the event loop the venue publishes from. Every "of order a
minute" in the tree was corrected to what was measured.

## 5. The defect this subphase found in the one before it

PH-20.1 shipped a browser suite that boots its own engine. **It was not testing
that engine.**

`next.config.mjs` carried `env: { OTC_API_BASE }`, and Next's `env` key
substitutes at _build_ time. A panel started with an explicit engine address
proxied to the baked-in default — and this machine had a stale engine on port
3000 whose markets had stalled 4,117 seconds past the catch-up bound. It answered
`/catalogue` and `/history` from stored state and published no ticks. So the
panel looked healthy, drew bars, and never moved.

That is why PH-20.1's suite passed repeatedly and then began failing with no
code change: the stale engine was publishing when those runs happened and had
stalled by the time of the later ones. The suite was green on a lie for part of
its life.

Two defects, not one:

- **the address was frozen at build time** — and `env` also inlines into the
  client bundle, so the engine's internal host travelled to every viewer;
- **the rewrite did not stream.** Replacing the rewrite with a route handler that
  hands `upstream.body` to the response unread was necessary and not sufficient:
  the first version still read the address once at module load and still talked
  to port 3000.

Both are guarded now by tests of _behaviour_. The test that used to live here
read `next.config.mjs` and asserted a rewrite existed; it passed for a week while
the rewrite silently failed to stream. **A test of a configuration value is not a
test of the behaviour that value was chosen for.**

## 6. Plants

Ten, all caught, tree restored and verified by digest after each.

| Planted defect                                         | Caught by                          |
| ------------------------------------------------------ | ---------------------------------- |
| proxy reads the body before responding                 | streams-what-arrives-after         |
| engine address resolved once at module load            | reads-address-at-request-time      |
| `next.config` inlines the address into the bundle      | keeps-address-out-of-bundle        |
| event stream left bufferable                           | tells-intermediaries-not-to-buffer |
| `Last-Event-ID` dropped                                | forwards-Last-Event-ID             |
| chart container sizes to its content                   | 3 of 5 browser tests               |
| engine not proxied under the panel's origin            | 5 of 5 browser tests               |
| live price frozen                                      | shows-a-price-that-moves           |
| stream stays subscribed to the first asset             | switches-the-whole-screen          |
| history fetched for whichever asset was selected first | switches-the-whole-screen          |

The harness itself had a defect worth recording: for a plant that edits one file
twice it restored the snapshots in order, leaving the file in its intermediate
state, and three later plants failed for that reason rather than their own. It
restores in reverse and asserts a digest match now.
