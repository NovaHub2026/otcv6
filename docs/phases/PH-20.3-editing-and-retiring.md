## 1. The editable surface is one field

An asset has an id, a family, a display name, a reference price, a lattice, a
personality and a body of recorded evidence. Exactly one of those may change
after the asset exists.

| Field              | Why it cannot change                                           |
| ------------------ | -------------------------------------------------------------- |
| `id`               | it derives the keystream (ADR-0002) — a new id is a new market |
| `logQuantum`       | it decides every settlement (ADR-0004)                         |
| `referencePrice`   | it maps those integers to the numbers a viewer already read    |
| `displayPrecision` | a coarser display hides a move a contract settled on           |
| `traits`, `family` | the personality _is_ the market                                |
| `evidence`         | it is the record of what was measured, not a setting           |
| **`displayName`**  | **presentation, never compared against — this one may change** |

Each is refused **by name**, and the message says which invariant it protects.
`OVERLAY_FIELDS` is a closed list, asserted as such, because the failure worth
preventing is a future field being added to the overlay because it was
convenient.

## 2. Overlays, so a compiled asset is administrable too

Five assets are compiled into `ASSET_CATALOGUE` and were never registered
anywhere. Renaming one still has to work, so the operator's edits live in an
overlay keyed by asset id rather than inside the registration:

```
_overlays.json   { "gbpjpy": { "displayName": "Sterling / Yen" },
                   "xauusd": { "retiredAt": 1788330000000 } }
```

The leading underscore is load-bearing. An asset id must match
`^[a-z0-9][a-z0-9._-]{0,63}$`, so no asset can ever produce that filename — it
was `overlays.json` for one test run, and `list()` duly tried to read it as a
registration and refused the whole catalogue. `list()` now reads only files whose
name is a legal asset id.

## 3. Retirement is final

A retired market stops being hosted. Nothing it published is removed, rewritten
or replayed: every checkpoint, candle and journal entry stays where it was, and
the history endpoint keeps answering. Retiring is a decision to stop generating
and says nothing about the past (INV-009).

There is no un-retire, and that is a product decision rather than a missing
feature. A market resumed after a gap has two options and both are bad:

- **invent the interval** nobody generated — which this runtime already refuses
  outright, by the catch-up bound (ADR-0010);
- **take a seam** in the published record — a discontinuity an operator would be
  choosing to put into a market that had already printed prices.

So the confirmation on the panel says "for good" rather than implying an undo
that does not exist, a second retire is a 409, and `start()` does not resume a
retired market. Recorded in `docs/decisions/DECISION-LOG.md`.

## 4. What this changed outside the two endpoints

**CORS.** `main.ts` allowed any origin, with a comment explaining that the
service was entirely read-only. That stopped being true in PH-20.2. The wildcard
default now allows `GET` and `HEAD` only; a deployment that genuinely drives this
from another origin names it in `OTC_CORS_ORIGIN` and gets the write methods with
it. The panel needs neither — it proxies the engine under its own origin.

**The proxy's method list.** A Next route handler serves only the methods it
exports. `PATCH` was missing for one build and the panel's rename silently did
nothing; the browser test caught it because it checks the name on the screen
rather than the status of a request.

## 6. Evidence

```
apps/api/src/registration.stat.test.ts   4 passed  (21.9s)
apps/web/src/panel.stat.test.ts          6 passed  (39.2s)
```

The API acceptance renames a **compiled** asset, refuses four immutable fields by
name, retires a market that is actively publishing, confirms its history still
answers, gets a 409 on a second retire, SIGKILLs the process and finds the market
still retired. The browser acceptance does the same through the panel and then
checks the preview screen: the renamed asset is live under its new name, the
retired one reports that it is not hosted.
