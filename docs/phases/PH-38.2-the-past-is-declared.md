# PH-38.2 — The Past Is Declared, And Only What Can Be Evidenced

Type: SUBPHASE TECHNICAL DOCUMENT
Identifier: PH-38.2
Parent: [PH-38](PH-38-the-frame-a-price-counts-in.md)
Status: PLANNED
Created: 2026-09-24

---

## 1. Objective

Give the 3,728,119 ticks the live record holds from before the v2.4.0 relattice
the frame they were actually published on, on the Human Owner's instruction of
2026-09-24 (`DECISION-LOG.md`) — and declare **nothing** that the record cannot
corroborate.

## 2. Why this is a declaration and not a migration

PH-38.1's constructor writes no epoch on upgrade, and that stays true. A
migration runs at open, on any deployment, with no catalogue, no operator and no
way to check itself; the only thing it can do honestly is leave the range
undeclared. This subphase is the opposite situation: a deliberate act, run once,
by someone who can look at what it proposes before it is written.

## 3. The evidence, and what it refuses

The criterion is the one measured in the phase document §3. At the relattice
boundary the resume re-expressed the price, so for the correct boundary `R` and
the correct old frame `F`:

```
displayPrice(last tick before R, F)  ≈  displayPrice(first tick at R, current frame)
```

Measured across the catalogue: **median gap 0.0066%, within 0.1% on 30 of 30**.
At an ordinary restart seam the same comparison is off by about **30%**. The
acceptance band is therefore 0.1% against a ~30% alternative — four orders of
magnitude of separation, which is what makes this evidence rather than a
plausible story.

The tool refuses, by name and without writing anything, when:

- no seam in the record passes the check for that asset — including the case
  where the asset has been trimmed past its boundary, which is the **expected**
  answer as the window advances, not a failure;
- more than one seam passes, so the boundary is ambiguous;
- the asset has no `LATTICE_BEFORE_PH37` entry, which is every
  operator-registered asset outside the compiled thirty. It is refused by name
  rather than defaulted;
- an epoch already exists for that asset, unless `--replace` is given.

A refusal for one asset never stops the others, and nothing is written for a
refused one.

## 4. What is built

`npm run state:lattice` in `tools/sim`, three verbs, insert-only into the
`lattice` table:

| Verb                                                               | What it does                                                                                   |
| ------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------- |
| `list --dir DIR`                                                   | every asset's declared epochs, and its undeclared range if any                                 |
| `check --dir DIR --from-release v2.4.0`                            | finds each boundary, prints the continuity gap and the two rendered prices, writes **nothing** |
| `declare --dir DIR --from-release v2.4.0 [--asset ID] [--replace]` | writes what `check` printed, per asset, refusing what it cannot evidence                       |

`check` exists so that `declare` is never the first time anyone sees the
numbers. It prints, per asset, the boundary sequence, the gap, and what the last
pre-boundary tick renders as before and after — `1.202006 → 1.163199` for
`eurusd-otc`.

Two epochs are written per asset, not one: `[oldest, R)` on
`LATTICE_BEFORE_PH37`'s frame and `[R, …)` on the current frame. Declaring only
the first would leave the record saying the old frame is still in force.

`verifyStateDirectory` learns three checks, so `state:verify` and every backup
carry them: epochs are strictly increasing per asset, an epoch's `from_sequence`
is not above the record's head, and an asset with a declared epoch has no tick
older than its oldest epoch that the epoch does not cover.

## 5. Guards, each to be watched failing

- **The wrong seam is refused.** Point the tool at the 04:44:49 seam — the one
  a first pass at this actually mistook for the boundary — and it must refuse:
  the gap there is ~30%, not ~0.007%. This is the guard the whole subphase turns
  on, because the failure it prevents is the one that already happened once.
- **A near-miss frame is refused.** A quantum wrong in its last bits renders a
  price wrong below `displayPrecision` and is invisible forever — Cycle Audit
  12's finding 6 in a new costume. Feed a frame off by 2.58× (the audit's own
  number) and by one part in 10⁶, and both must fail the continuity check.
- **A trimmed asset is refused, not defaulted.** Trim past the boundary and the
  tool must say the range is gone rather than declare from the oldest tick.
- **An unknown asset is refused by name.**
- **The declared record renders what was published.** End to end on a real
  `MarketController`, against the previous release's own artefact: a
  pre-boundary tick must render as the string `v2.4.0` printed for it, which is
  the only statement of correctness that does not depend on this release's
  arithmetic being right about itself.

## 6. What it does not fix

The jump a broker's own books recorded at the boundary is not undone. The venue
becomes right about its history; a client that already derived and stored a
display price stays wrong, and the only levers for that are the contract version
and the conformance suite. PH-38.3 is what makes the read routes use these
epochs at all — until it lands, declaring changes what the record _can say_ and
not yet what a route _answers_.
