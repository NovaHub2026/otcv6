## 1. Objective

Leave nothing open by accident. Every Issue on the tracker is closed with a
fix, or closed with a decision recorded where the next reader will find it, or
left open **by name** with whose it is. The integration package is regenerated
from the tagged commit and validated standalone. The release is a record — the
commit, the gate, the served verdict, the conformance run, the restart the run
included, the ceilings a broker plans against — not a sentence in a handoff.

## 2. What is run

- The Issue tracker is walked once. For each open Issue: fixed in scope
  (#20, the Int32 narrowing), closed by decision (#4, #7, #8, #12, recorded in
  `DECISION-LOG.md` under 2026-09-06), or left open by name (#9 the multi-node
  composition, deferred by the Cycle 10 plan; #3 and #14, Governance
  amendments, the Human Owner's).
- `tools/sim/scripts/integration-package.sh v1.0.0 <out>` regenerates the
  package from the tag; the package's own unit suite is run standalone.
- `docs/evidence/RELEASE-1.0.0.md` records the release: commit, gate exit and
  duration, hosted CI, the served verdict (PH-30.4) and the conformance run,
  the restart the run included, the observer ceiling (PH-30.3), the record's
  cost per tick (PH-28), the contract version and digest, and what is
  deferred by name.
- The phase gate runs on the closing tree; the phase is approved from it; the
  merge to `main` is tagged `v1.0.0`.

## 3. Acceptance criteria

1. No open Issue without a recorded decision or a named owner.
2. The regenerated package builds and its unit suite passes standalone, with
   the file count and test count recorded.
3. `RELEASE-1.0.0.md` exists, indexed in `DOCS_INDEX.md`, and every number in
   it points at the record it comes from.
4. `v1.0.0` is a tag on the merge commit, and `CURRENT_STATE.md` names it.
