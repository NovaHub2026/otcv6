## 1. What five assets hid

The sidebar was an unsorted flat list, and for five assets that is not a
shortcut — it is the right design. At a hundred it stops working, and the
failure is not visual: the operator's question changes from _which of these_ to
_where is the one I want_, and a list answers only the first.

The same is true of the Assets screen, which is a table with one row per asset.

## 2. Two pure functions, and why they are not in the component

`apps/web/src/lib/catalogueView.ts`:

- `filterCatalogue(entries, query)` — substring, case-insensitive, over id,
  display name and family, with space-separated terms conjunctive.
- `groupByFamily(entries)` — families in **first-appearance** order.

Both are pure and outside React deliberately. Filtering is the kind of thing that
looks obviously right and is quietly wrong at the edges, and the edges are where
a panel gets embarrassing:

- a **blank query shows everything**, not nothing — a filter that hides the
  catalogue until something is typed is a filter that broke the screen;
- **substring, not prefix** — an operator looking for the dollar pairs types
  `usd` and means `eurusd`, `btcusd` and `xauusd`;
- **first-appearance grouping, not alphabetical** — alphabetical order moves
  every group the first time a new family gains a member, and a list that
  rearranges itself is a list nobody learns.

Eleven unit tests cover those, including a hundred assets across eight families.
A component test could not have covered them at that resolution.

## 3. What only a browser could show

That the box is wired to the function and that the list actually shrinks. The
seventh browser test filters by id, by family, and by a string that matches
nothing, then clears the filter — and checks the **chart never stopped**, because
filtering narrows the list and never the selection. An operator who types a query
has not asked to stop watching the market on screen.

## 4. Evidence

```
apps/web/src/lib/catalogueView.test.ts   11 passed  (unit)
apps/web/src/lib/priceFormat.test.ts      6 passed  (unit, §5)
packages/chart/src/bars.test.ts          20 passed  (unit, §5)
apps/api/src/adminSurface.test.ts        67 passed  (unit, §5)
apps/web/src/panel.stat.test.ts           8 passed  (browser, 47.0s)
```

The browser suite runs where a browser can launch. On a host without
`libnss3`, `libnspr4` and `libasound2` it reports its tests as **skipped** —
not passed, which is what it did until the out-of-band audit of 2026-09-02
(a6-03) — and hosted CI installs the libraries and sets `OTC_REQUIRE_BROWSER=1`,
so a missing browser fails the run there.

The browser line above was executed on this host under `OTC_REQUIRE_BROWSER=1`,
against a Chromium made loadable by an `LD_LIBRARY_PATH` prefix built by hand
(§5.2). That prefix is session-local and outside the repository, so **the
authority for this subphase's browser evidence is the hosted run**, which builds
its own environment from `ci.yml` and is reproducible by anyone. The local run
is what made the two defects measurable while they were being fixed.

## 5. What the Human Owner found while this was open

Two defects in the same panel, neither about scale, both reported from a screen
rather than a test — which is how the last five panel defects were found too
(PH-20 §1).

**A price label that was not a number.** The axis read `1.91146.5` and
`1.87649.8`, each with two decimal points. The prices were right; the format was
not. Lightweight Charts renders the fraction by left-padding
`fracPart * minMove` and slicing to `precision` characters, and the panel
declared `precision: 7` against a hard-coded `minMove: 1e-8`. Those disagree, the
product came out non-integer, and the slice cut through its decimal point:
`('0000000000791146.5').slice(-7)` is `'91146.5'`. Only a price with more
decimals than the precision could trigger it, which is why the axis ticks and
the candles were right for months: they come from history already rounded, and
the live tick was the one value converted at full float precision _and_ drawn as
text. `apps/web/src/lib/priceFormat.ts` derives `minMove` from the precision —
they are one decision — and rounds the live price to the digits the asset
settles on. The test reproduces both labels exactly.

**A candle that stood still for up to an hour.** The live price line moved and
the newest candle did not, sitting far below it. Both halves were correct:
CA6-30 forbids rebuilding a bucket from a partial view, so a live bar is drawn
only for a bucket that began after the client connected — and the panel's
default timeframe is one hour. Neither rule had to give, because the record
holds the running bucket as complete **minute** bars, its permanent base tier.
`LiveBarBuilder.seedFrom` folds those in and the stream resumes at the tick
after the last of them, which is the record read finer than the chart draws
rather than a rebuild.

**And it stood still again**, because that fix rested on a resume the feed
frequently cannot serve. The panel resumes from where the _record_ stops; the
feed keeps a bounded window of ticks and a restart empties it, so the sequence
after the newest stored candle is routinely older than anything the feed still
holds. Refused, the panel dropped the resume and fell back to the conservative
rule — the frozen candle, again.

Hosted CI reproduced it while the local gate was green, which is precisely the
corroboration `GOVERNANCE.md` §40.1 exists for — run 33689094040, five failed
panel tests. What the log actually holds is worth stating exactly, because the
first account of it here was wrong and the closure audit caught it: **one** 400,
recorded as a browser console error on the resume, and two tests failing on a
status stuck at `live — reconnected after a gap`, which is the refusal loop seen
from the outside. The other five entries were `net::ERR_ABORTED` on normally
ended streams — the suite's own request filter matched the URL's tail, and the
tail had changed the moment `?from=` was added to it. A miscount in the
direction of "more evidence than there was" is the kind this project is
supposed to catch.

The endpoint now takes an opt-in **`onGap=live`**: a sequence it cannot serve
yields the live edge plus an explicit `gap` event naming what was skipped,
instead of a refusal. Told about the gap, the panel keeps drawing the forming
bucket **from the record** and re-reads it as it fills, while the price line
carries the live edge. And `LiveBarBuilder` no longer infers an exact join from
having been seeded: a seed is the record, a resumed stream is this client's, and
they may be joined only when the stream provably continues the seed
(`CATALOGUE_AND_PANEL.md` §5.2).

**A third defect, found while measuring the second.** Every asset switch logged
`Object is disposed`. React cleans effects up in the order they were declared,
so the effect owning the chart calls `remove()` before the effect owning the
price line releases it — and every method on a removed series throws. The price
line dies with the chart; there is nothing to release.

## 5.1 Two rounds of "still broken" that were about a different program

The Human Owner reported the candle unfixed twice after it had been fixed, and
both reports were right. The launcher served `~/.otc-audit7/fix` — the
out-of-band audit's worktree, parked on `main` — while the work happened in
`~/Projects/otcv6`. The browser was loading a bundle built hours before either
fix existed. Nothing was wrong with the fixes and nothing was wrong with the
reports; they were about different programs.

This is the third time this project has tested the wrong thing and believed the
answer: a panel talking to a stale engine on port 3000 while its own booted
unwatched (§5.1 of `CATALOGUE_AND_PANEL.md`), a suite reporting six browser
tests as passed while launching no browser (a6-03), and now a launcher serving
a tree nobody was editing. The shape is always the same — the instrument and
the subject drift apart, and the _evidence stays green or stays red for reasons
that have nothing to do with the change_. The launcher defaults to the working
tree now and prints the tree, branch and commit it served, so the next
disagreement about what is running is settled by reading one line.

## 5.2 A browser on a host without root

`a6-03` recorded that no Chromium could launch here, so the panel suite reported
its tests as skipped and only CI ever ran them. The missing pieces were three
system libraries — `libnss3`, `libnspr4`, `libasound2t64` — and they do not
need root: `apt-get download` them, `dpkg-deb -x` each into a directory, and
point `LD_LIBRARY_PATH` at it. The recipe now lives in `panel.stat.test.ts`
beside the message that tells a reader the suite was skipped, which is where
someone hitting the problem will actually be looking.

**What that prefix is, exactly, matters to anyone reading this record.** It is a
directory in a session scratchpad on `tmpfs`. It is not in the repository, it is
not a build output, and it does not survive a reboot — so a run that depended on
it is _not_ reproducible from a clean checkout without redoing the three
commands above. The closure audit reported this evidence as unsupported after
searching for the libraries with `find / -xdev`, which cannot cross into
`/tmp`; the libraries were there and the run did happen, and the auditor was
nonetheless right about the thing that counts. An evidence line has to say how
it was obtained when the answer is not "check out the repository and run the
gate".

## 5.3 What guards these now, and what the closure audit had to add

The price label and the candle are both invisible to a DOM assertion, because a
chart is painted on a canvas. That is why the first fix shipped with no browser
guard at all and why the second defect survived it.

- `apps/web/src/lib/priceFormat.test.ts` carries a copy of the library's own
  formatting algorithm and reproduces `1.91146.5` exactly.
- `packages/chart/src/bars.test.ts` pins that a seeded bucket without an exact
  join refuses live ticks; that a re-seed may not walk the bar backwards, judged
  against **the bar being drawn** rather than the last seed; and that the
  builder detects a broken join from the tick sequence itself.
- `apps/api/src/adminSurface.test.ts` pins the `gap` event, the unchanged
  default refusal, and a mistyped policy refused by name.
- `apps/web/src/panel.stat.test.ts` asserts, in a real browser, that the panel
  publishes a live bar **for the bucket now in progress** — the one fact that
  separates the defect from correct behaviour without reading a canvas.

Each was watched failing against the defect it guards, on this host.

**And then the closure audit found three more, in the fix itself.** Seven
independent readers, one per claim area, each told to falsify rather than
confirm; every finding put to an adversarial refuter before it counted. Twenty
survived. Three were defects in code written the same day:

- **A latch, not a state.** `joinExact` was declared once per effect and never
  reset, while `run()` is re-entered on every stream error. A reconnect that
  gapped a second time kept the optimistic builder and folded post-hole ticks
  onto a record seed — CA6-30's exact prohibition — with the status bar
  claiming the opposite. The fix is not a reset. `LiveBarBuilder` is given the
  **sequence** the stream was asked to resume at, and compares it against the
  first tick that actually arrives: a claim it can check rather than a boolean
  it must believe. The panel's flag now only decides what the viewer is told.
- **A guard that compared the wrong thing.** The re-seed direction check read
  `#seeded`, which `accept` never updates, so a builder that had advanced into a
  later bucket accepted a stale refresh of the older one and walked the newest
  bar back an hour. The auditor found it by executing the sequence rather than
  reading the guard, which is the difference between the two.
- **Two clock reads with an await between them.** The bucket being seeded and
  the instant the builder calls "when this client connected" came from separate
  `Date.now()` calls either side of a network round trip. A boundary landing in
  that window left neither able to draw — one live bar lost to the narrowest
  possible form of the defect this whole subphase is about. One read now.

It also caught the record over-claiming its own evidence: "five 400s" where the
CI log holds one, and a browser run reported without saying it depended on a
hand-built library prefix outside the repository. Both are corrected above.

## 6. What this does not do

**No virtualisation.** A hundred rows is a hundred DOM nodes and the browser does
not care; the measurement that would justify a windowing library has not been
taken, and adding one on the strength of a guess would be exactly the kind of
change this project is careful about. It is stated here so that whoever reaches a
thousand assets knows it was a decision rather than an oversight.
