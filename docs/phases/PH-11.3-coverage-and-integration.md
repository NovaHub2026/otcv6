## 1. Objective

Close B-003 — `tools/*` excluded from coverage measurement — and integrate the
phase.

## 2. What the item turned out to be

The stated item was one line of configuration: `coverage.include` listed only
`packages/*/src`, so the simulation runner, the evidence generators and the phase
acceptance suites were unmeasured. Excluding the code that **generates** every
number the project cites from the measurement of that project's quality is the
wrong way round.

Adding `tools/*/src` exposed a second layer. **`npm run test:cov` did not
complete**, so coverage was still effectively unmeasured. Two failures, neither a
defect in the code:

- a unit test that takes one second exceeded a five-second timeout, because v8
  instrumentation rewrites every function;
- a throughput assertion measured 183,265/s against a 200,000 floor, which is
  measuring the instrument rather than the engine.

Both are now coverage-aware through an explicit `OTC_COVERAGE=1` set by the
`test:cov` script — not a guess at Vitest's internals, so it cannot silently stop
working.

## 3. A guardrail was not weakened to make this convenient

The natural home for an `isMeasuringCoverage()` helper was `packages/core`. That
directory is scanned by the `no-ambient-state` guard, which bans `process.env`
from the price path — so putting it there would have required an allowlist
entry.

Weakening an invariant guard for test convenience is the pattern this project has
found six times. The timeout was solved in `vitest.config.ts` and the throughput
floor with one line in the test that owns it, each where it belongs.

## 4. Entry points are not excluded

`cli.ts` and `horizonEvidence.ts` read **0%**. Excluding them would have raised
`tools/sim` from 56.55% to something flattering and meant nothing. A script no
test drives should read as uncovered, because it is.

They were smoke-tested by hand instead — the distinction between "never
exercised" and "broken" is worth knowing, and the CLI had never been run by
anything. It works.

## 5. What measuring coverage found that was not coverage

Instrumentation slows execution five to ten times, which makes it an unintended
**detector for event-loop starvation**: a synchronous block that always survived
at 3 seconds fails at 30.

It surfaced the third recurrence of B-005's class. `withheld.stat.test.ts` used
the synchronous `runBattery` where `runBatteryAsync` already existed, and its
cross-asset case ran **627 seconds** of uninterrupted CPU. `edge.ts`'s directional
estimator had the same shape and now has a generator core with an async wrapper,
matching `calibrateAssetCore` and `runBatteryAsync`.

### The guard B-010 said was impossible

B-010 recorded that no static guard could see this class, because the offending
loop is bounded at a small number while `distributionConsistency` loops 800 times
and is fine — the difference is per-iteration cost, invisible in the source.

**That was right about loops and wrong about entry points.** All three
recurrences went through a function whose yielding twin already existed and sat
two characters away in the import list. `testCost.test.ts` now fails when a
`*.stat.test.ts` imports `runBattery`, `runSimulation`, `calibrateAsset` or
`estimateDirectionalEdge`.

The escape hatch is spelled as an alias — `calibrateAsset as calibrateAssetSync`
— because `catalogue.stat.test.ts` legitimately tests the synchronous variant's
refusals. That puts the intent at the call site rather than in a config file
nobody reads.

Watched failing against two plants: a direct import, and an attempt to slip past
with a generic alias. Both caught.
