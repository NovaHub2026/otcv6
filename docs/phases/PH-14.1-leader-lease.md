## 1. Objective

Admit exactly one leader per asset, prove it, and make a former leader unable to
write even while it still believes it leads.

[ADR-0012](../decisions/ADR-0012-single-writer-generation.md) established _why_
generation is single-writer. This subphase builds the mechanism and the evidence.

## 2. Mutual exclusion is the easy half

Granting one lease at a time is a compare-and-set. The hard half is the interval
between losing a lease and knowing it: a leader partitioned from the store keeps
generating and keeps trying to persist, and expiry alone does nothing to stop
it — expiry is a fact at the store, not at the stranded node.

So the lease is worth nothing without the second mechanism. Every grant carries a
**fence token**, monotone per asset, and the _resource_ refuses a write whose
token is not the current grant. The stranded leader is stopped by the store it is
writing to, not by its own belief about time.

## 3. The store judges expiry, not the caller

A node never compares its own clock against `expiresAt` to conclude it still
leads. It asks, or it writes and is refused.

This removes clock skew from the safety argument entirely, and — less obviously —
from the liveness argument too. If each node judged expiry locally, a node with a
fast clock would declare a healthy leader dead and take over, and fencing would
turn that into an availability loss rather than a correctness one. With one clock
deciding, skew between nodes cannot cause a handover at all.

`AssetLease.expiresAt` is therefore documented as advisory: it exists to schedule
renewals, and nothing may branch on it.

## 4. Tokens move on acquisition, not renewal

A renewal that bumped the token would fence the live leader's own in-flight
write. An acquisition that did not bump it would let a returning leader write
under a token another node had already used.

So: **renewal preserves the token; every acquisition increments it.** This
includes reacquisition by the same node after its own lease expired, because
during that window another node could legitimately have led and written.

The consequence, which is the property worth testing: across the whole life of an
asset, grant tokens are strictly increasing, so no two grants ever share one, so a
stale writer's token can never equal the current grant's.

## 5. The lease and the state live in one store

The fence check and the record write must be atomic with respect to each other.
Two stores cannot give that without a distributed transaction, and a check
followed by a write to a different store is not fencing — it is a race with a
comment.

So `CoordinatedStore` is one interface over both: it grants leases and it writes
records, and `saveFenced` is a single atomic section. The shipped implementation
is in-memory, where "atomic" means the critical section contains no `await` and
therefore cannot interleave under Node's execution model.

A deployment store (a database row with a conditional update, an object store
with a compare-and-set precondition) implements the same interface. To make that
substitution safe, the contract is **executable**: `describeCoordinatedStore` is
a conformance battery any implementation must pass, so a future backend is
checked against the same twenty-odd properties rather than against prose.

## 6. Holder identity is per process, not per node

A restarted process does not reclaim its predecessor's lease; it waits out the
term. Reclaiming would be faster, and it would rest on "the old process is
certainly gone", which a hung process disproves at exactly the moment it matters.

The cost is bounded by the term and is paid only on restart.

## 7. The term is 15 seconds, tied to the catch-up bound

[ADR-0010](../decisions/ADR-0010-catch-up-bound.md) set the catch-up bound to 15
seconds. The lease term matches it, and the tie is the argument:

- A leader that cannot renew for a full term is a leader that has been out of
  contact for longer than it is allowed to catch up. Its next advance would be
  refused by `CatchUpTooLargeError` anyway, so losing the lease takes nothing
  away that the bound had not already taken.
- The maximum leaderless window equals the maximum catch-up burst, so failover
  cannot produce a gap larger than one the running system already tolerates.

Renewal is attempted every 5 seconds — three attempts per term, so two lost
round-trips are survivable.

## 8. What is built

`packages/runtime/src/lease.ts`

- `LeaseGrant` — assetId, holder, token, grantedAt, expiresAt.
- `LeaseStore` — `acquire`, `renew`, `release`, `inspect`.
- `CoordinatedStore` — `LeaseStore` and `StateStore` in one, plus `saveFenced`.
- `MemoryCoordinatedStore` — the reference implementation.
- `AssetLease` — the holder-side handle: `renew`, `release`, `lost`.
- `StaleFenceError`, `LeaseHolderError`.

`packages/runtime/src/leaseConformance.test.ts` (corrected 2026-09-02; the phase document named a `.ts` file that never existed) — `describeCoordinatedStore`, the
executable contract.

## 9. Verification

| Claim                                                          | How                                          |
| -------------------------------------------------------------- | -------------------------------------------- |
| Exactly one of N concurrent acquirers wins                     | conformance battery, N = 2 … 64              |
| Expiry frees the lease without the holder's cooperation        | conformance battery                          |
| Tokens strictly increase across every grant for an asset       | conformance battery, 200-grant sequence      |
| Renewal preserves the token                                    | conformance battery                          |
| Reacquisition after expiry by the same holder increments it    | conformance battery                          |
| A former leader's write is refused and the record is unchanged | conformance battery                          |
| A leader whose lease expired but was untaken is also refused   | conformance battery                          |
| Grant intervals for one asset never overlap                    | conformance battery                          |
| The lease path reads no ambient clock and no ambient state     | existing guardrail scan (`REPLAYABLE_ROOTS`) |
