# PH-24.1 — The Selectable Sign Source And Its Hook

## 1. Objective

Build the one thing every Lab control needs and the one thing that must never
reach production: a sign source that plays a chosen vector into a hosted
engine, **composed only in the Lab**, and guarded before anything is built on
it.

The boundary comes first because it is the part that can be wrong in a way that
matters. A control wired before the boundary is a control that exists somewhere
it should not, for however long the boundary takes.

## 2. Mechanism

`SelectableSigns implements RandomSource`, under `apps/api/src/lab/`. It wraps
the keystream's `sign` stream:

- **transparent** by default — `nextBoolean()` returns the inner draw;
- **armed** after `arm(signs)` — the next `signs.length` calls return the
  scripted bits **and draw the inner stream for each**, so the keystream cursor
  advances exactly as it would have (this is `ScriptedSigns` from
  `stepIndependence.test.ts`, which already proves the steps are unaffected);
- **released** by `release()` or by exhaustion — transparent again;
- `position()` and `seek()` delegate to the inner stream, so a snapshot taken
  mid-script records the keystream cursor and nothing else. A restart is a
  release, by construction.

Arming happens **between advances**, through `VenueService`, with the same
`await this.inFlight` discipline `retire` uses (ADR-0012).

## 3. The hook, and where it is not

`resumeMarket` constructs engines at three sites (fresh, restored, seam) via
`createMarketEngine`, which already accepts `streams`. `ResumeOptions` gains
`signSource?: (keystream: RandomSource) => RandomSource`, default identity, and
`VenueService` passes through what it was given. `AppModule` becomes
`AppModule.register(options?)`; `main.ts` registers it with nothing;
`lab.main.ts` registers it with the Lab's factory.

**The production composition cannot be given a sign source.** That is asserted,
not promised:

1. an architecture test reads `main.ts` and `app.module.ts` and asserts no
   `signSource` is registered there, and reads `resume.ts` and asserts the
   default is identity;
2. `labSurface.test.ts` already forbids `app.module.ts` from reaching anything
   under `lab/`, which is where `SelectableSigns` lives;
3. a plant that registers a sign source in `main.ts` is caught by (1).

## 4. What this subphase may not do

- Change any tick the engine would produce unarmed: the wrapper is identity when
  transparent, and a test compares 1,000 ticks through the wrapper against
  1,000 without it.
- Persist a script: snapshots carry keystream cursors only.
- Expose `arm` on anything the production composition instantiates.

## 5. Acceptance criteria

1. Transparent, the wrapper is invisible: identical ticks, identical cursors.
2. Armed, the engine's next N signs are the script and its steps, intervals and
   rounding are unchanged (`stepIndependence` re-asserted through the wrapper).
3. After the script, the keystream cursor is exactly where it would have been
   unscripted, and the continuation is the keystream's.
4. A snapshot taken mid-script, restored into a fresh engine, continues on the
   keystream — the cursors never learned a script existed.
5. The production composition registers no sign source (architecture test),
   and a plant that does is caught.
6. `SelectableSigns` is reachable from `LabModule` and from nothing `AppModule`
   composes.

## 6. Scope

- `apps/api/src/lab/selectableSigns.ts` (+ test)
- `packages/runtime/src/resume.ts` — the optional `signSource`, default identity
- `apps/api/src/app.module.ts`, `main.ts`, `lab/lab.main.ts`,
  `venue.service.ts` — the registration and pass-through
- `apps/api/src/composition.test.ts` — the architecture guard of §3

**Excluded:** every route that uses it (PH-24.2 onward).
