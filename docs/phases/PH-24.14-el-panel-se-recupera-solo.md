## 1. Objective

The Human Owner's tab was open while this session restarted the engine and the
panel for PH-24.13. The requests of those seconds failed, and the screen they
sent shows what the panel did with that: the chart read «Failed to fetch · 0
velas» and stayed there, and the Lab wore «No hay ningún Lab configurado» for
what was a five-second outage. A fresh page was live the whole time after.

Two defects, both the panel's. The chart's first load has no retry: the stream
reconnects with backoff on every later interruption (PH-22), but a `run()` that
fails at the start ends in a status line and nothing more. And the Lab's notice
says "not configured" for every failure, including a transport error, when only
the proxy's own 503 means that.

## 2. What is built

- **The chart's first load retries** through the same `retryLater` backoff the
  stream uses, so a chart opened during an outage draws itself when the engine
  answers again.
- **The Lab's notice says what happened**: a transport failure reads «no se
  alcanza el Lab» with the reason behind ⓘ; «No hay ningún Lab configurado» is
  reserved for the proxy's answer that no Lab base is configured. Both clear on
  the next successful poll, as before.

- **A gate never touches the served panel.** The browser suites built the
  panel into `.next` — the directory the operator's local panel serves — so
  every targeted gate rewrote the served build under a running server, and the
  Human Owner's tab broke with «a client-side exception» twice on 2026-09-03.
  `next.config.mjs` reads `OTC_NEXT_DIST_DIR`; both suites build and start from
  `.next-stat`. The operator's `.next` is written only by the launcher.

## 3. What this subphase may not do

- Hide a failure: every retry says it is retrying, with the attempt count.

## 4. Acceptance criteria

1. A guard proves the chart's first `run()` failure goes to `retryLater`, and a
   plant removing it is caught.
2. The notice distinguishes the two reasons (guarded).
3. Both browser suites build and start from `.next-stat` (guarded, planted);
   a targeted gate runs with the local panel open and the panel keeps serving.
4. Targeted gate.
