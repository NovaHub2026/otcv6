## 1. Objective

Give a broker's operator what an orchestrator, a monitor and a runbook need
from the venue, and ship the files a deployment starts from.

## 2. What is built

- **`GET /health/live`** — `200 {"live": true}` as soon as the process serves
  HTTP; nothing about the markets. **`GET /health/ready`** — `200` once every
  market has resumed, the record has primed and the venue is publishing;
  `503` with `{"ready": false, "reason"}` before that and while any market is
  stalled. `/health` stays as it is for humans and carries `ready`.
- **`GET /metrics`** — the Prometheus text format, from the values the venue
  already holds: markets hosted, stalled, ticks published (counter), stream
  subscribers, replay bytes in use, record head per asset, process uptime and
  resident memory. No new state; a scrape reads what `/health` reads.
- **Rate limits.** A per-client token bucket on every read route (by remote
  address, `OTC_RATE_LIMIT_PER_MINUTE`, default 600; the stream routes count
  the connection, not the frames): a flood answers `429` with `Retry-After`.
  The admin credential (`OTC_ADMIN_TOKEN`, a6-01) already guards every write
  and is documented as the credential, not the proxy rule, in the runbook.
- **`deploy/`** — `otc-engine.service` (systemd, `SIGTERM`, the state
  directory, the secrets file), `Dockerfile` and `docker-compose.yml` (engine
  and panel, a volume for the state directory, healthcheck on `/health/ready`),
  `nginx.conf` (SSE unbuffered, admin routes cut), and `backup.sh` (the
  `state:backup` command on a timer, keeping the last N). The guide's §8 points
  at them; the contract lists the new routes under a new version.

## 3. Acceptance criteria

1. `/health/live` answers before `start()`; `/health/ready` is `503` until
   every market resumed and `200` after; a stalled market turns it `503`
   again with the asset named.
2. `/metrics` parses as Prometheus text and its counters agree with `/health`
   and the feed's subscriber counts.
3. A client past the limit is refused with `429` and `Retry-After`; the next
   window admits it; the stream's frames are not counted.
4. The contract's version moves (the routes are new) and `contract.test.ts`
   passes; the conformance suite passes the new routes.
5. The deployment files are exercised: the compose file builds and the
   service comes up ready (a test that runs `docker` is optional and skipped
   without it; the systemd unit is linted by `systemd-analyze verify` when
   present, else parsed by the test itself).
6. Every guard watched failing.
