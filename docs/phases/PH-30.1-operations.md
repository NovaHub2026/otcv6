## 1. Objective

Give a broker's operator what an orchestrator, a monitor and a runbook need
from the venue, and ship the files a deployment starts from.

## 2. What is built

- **`GET /health/live`** — `200 {"live": true}` as soon as the process serves
  HTTP; nothing about the markets. **`GET /health/ready`** — `200` once every
  market has resumed, the record has primed and the venue is publishing;
  `503` with `{"ready": false, "reason"}` before that and while any market is
  stalled. `/health` stays as it is for humans and carries `ready`.
- **`GET /metrics`** — the Prometheus text format, from the values the venue
  already holds: markets hosted, stalled, ticks published (counter), stream
  subscribers, replay bytes in use, record head per asset, process uptime and
  resident memory. No new state; a scrape reads what `/health` reads.
- **Rate limits.** A per-client token bucket on every read route (by remote
  address, `OTC_RATE_LIMIT_PER_MINUTE`, default 600; the stream routes count
  the connection, not the frames): a flood answers `429` with `Retry-After`.
  The admin credential (`OTC_ADMIN_TOKEN`, a6-01) already guards every write
  and is documented as the credential, not the proxy rule, in the runbook.
- **`deploy/`** — `otc-engine.service` (systemd, `SIGTERM`, the state
  directory, the secrets file), `Dockerfile` and `docker-compose.yml` (engine
  and panel, a volume for the state directory, healthcheck on `/health/ready`),
  `nginx.conf` (SSE unbuffered, admin routes cut), and `backup.sh` (the
  `state:backup` command on a timer, keeping the last N). The guide's §8 points
  at them; the contract lists the new routes under a new version.

> **Corrected 2026-09-06 (Cycle Audit 10, a5-04).** There is no panel service
> and there never was: `docker-compose.yml` defines `engine` and `backup`, and
> `deploy/Dockerfile` copies no `apps/web`. The panel is a separate Next.js
> process, run as INTEGRATION.md §6 describes. The compose file's own header
> said "the engine and the panel" too; both now say what the file contains, and
> `deploy.test.ts` holds the title to the services the file defines.
>
> The `backup` service also could not work. It ran `image: node:24-slim` with
> the repository bind-mounted read-only and executed `deploy/backup.sh`, which
> runs `node tools/sim/dist/stateTool.js` — a path `.gitignore` excludes, so on
> a fresh clone the first run died with `Cannot find module`, the loop's
> `|| echo "backup failed"` swallowed it, and the service slept six hours at a
> time reporting healthy with zero backups written. It now builds and runs the
> same image as the engine (which copies `deploy/` and owns `/backups`), and
> `backup.sh` makes its first run fatal. Criterion 5 below is the reason nothing
> saw it: the docker test it promised was never written, and the guard that
> exists read the compose file for strings.

## 3. Acceptance criteria

1. `/health/live` answers before `start()`; `/health/ready` is `503` until
   every market resumed and `200` after; a stalled market turns it `503`
   again with the asset named.
2. `/metrics` parses as Prometheus text and its counters agree with `/health`
   and the feed's subscriber counts.
3. A client past the limit is refused with `429` and `Retry-After`; the next
   window admits it; the stream's frames are not counted.
4. The contract's version moves (the routes are new) and `contract.test.ts`
   passes; the conformance suite passes the new routes.
5. The deployment files are exercised: the compose file builds and the
   service comes up ready (a test that runs `docker` is optional and skipped
   without it; the systemd unit is linted by `systemd-analyze verify` when
   present, else parsed by the test itself).

   > **Corrected 2026-09-06 (Cycle Audit 10, a5-04).** No such test was
   > written, optional or otherwise, and `docker` is not installed in the
   > environment this project is developed in, so the docker path has never
   > been executed. What `deploy.test.ts` now checks instead, without docker:
   > every service is built from `deploy/Dockerfile`, none bind-mounts the
   > host's checkout, every file a service's command runs — and every file
   > those files run in turn — is inside the image's `COPY` set, and
   > `deploy/backup.sh` is actually run against a scratch state directory and
   > must write a backup and prune to N. The docker build itself remains
   > unexercised, and this document should not have said it was.

6. Every guard watched failing.

## 5. What the subphase found

1. **Readiness is not the absence of a crash.** The venue is ready once every
   market resumed and primed and none is stalled; a stalled market is alive
   and not ready, which is the difference an orchestrator needs.
2. **The health stub in `adminSurface.test.ts` had no readiness**, so the
   response carried `undefined` where the contract says a boolean; the
   contract guard would have caught it on the live venue, and the stub gained
   the field.
3. **A compose file's quotes belong to Prettier**; the deploy test matches
   either.
