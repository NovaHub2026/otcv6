## 1. Verified where it will actually be wrong

Every piece of PH-18 has its own tests. None of them can show that the panel and
the engine **agree**: that the bars a chart draws are the bars the record holds,
that switching timeframe re-reads one record rather than fetching a different
one, and that the live stream continues the history rather than restating it.

So the acceptance boots the real service with `OTC_BACKFILL_DAYS=2`, waits for it
to provision five markets, and drives the real client-side conversion over HTTP.
The two times this project found an architectural boundary defect — PH-5.3's
restart, PH-8.2's browser build — it was by running the real thing across a real
boundary rather than by reasoning about the pieces either side of it.

Seven checks, all against a live process:

| What it asserts                                          | Why it can only be checked here                 |
| -------------------------------------------------------- | ----------------------------------------------- |
| The catalogue renders, with every asset hosted           | provisioning, wiring and serialisation together |
| The provisioned history is contiguous at 1h              | the backfill wrote through a real database      |
| Every timeframe folds to the same record (INV-004)       | two endpoints, one stored record                |
| A sub-minute request is refused, not coarsened           | the refusal has to survive the HTTP layer       |
| Bars are the record converted, extremes intact           | real server output through the real bridge      |
| The venue goes on recording after provisioning ends      | only wall-clock time produces a stored bar      |
| The live stream continues the history, never restates it | the join exists only across a socket            |

## 2. What "goes on recording" costs to test

Nothing but time, and there is no shortcut: a minute bar closes on the wall
clock. The test reads the head of the stored minute series, waits, and requires
it to advance.

The "60 seconds of stored history in 65 seconds of wall clock" this originally
recorded is **an artefact of where the poll started**, not a measurement
(CA6-44): the test polls every five seconds until the head moves by one bar, so
the elapsed figure is uniform on [0, 60] plus polling granularity, and a later
run printed "60s in 15s". What the test establishes is that the head advances at
all, which is the property; the ratio was never a number.

This is the half of the Human Owner's requirement that provisioning does not
cover — "ninety days of history and then we go on saving everything in real
time" — and it was the one thing PH-18's other tests could not see.

## 3. Every guard watched failing

Five defects planted against the boundary, each reverted immediately:

| Planted defect                                                   | Failures |
| ---------------------------------------------------------------- | -------- |
| The history endpoint reads the wrong tier for a coarse timeframe | 1        |
| Provisioning is skipped, so a new market has no past             | 4        |
| The venue never records what it publishes                        | 1        |
| The catalogue is served without its dispersion                   | 1        |
| A sub-minute request is answered instead of refused              | 1        |

Two were uncaught on the first attempt:

- **The venue never records what it publishes** survived because every
  assertion read history that _provisioning_ had written. Continuous persistence
  — the explicit second half of the requirement — had no test at all. The
  wall-clock test above is the fix.
- **The live builder restates a bar history already owns** survived because in
  this configuration it cannot: the last stored bar is a closed minute, live
  ticks are in the current one, and the buckets never collide unless the stream
  replays. The guard is right and the plant belonged against
  `packages/chart/src/bars.test.ts`, where PH-18.2's campaign caught it. Recorded
  rather than quietly re-run, because "the plant was aimed at the wrong test" and
  "the guard is untested" look identical in a summary.

A third correction: the timeframe-agreement check first compared the two series
**by index**, and they are offset — the hour containing the window's start
begins before it, so the coarse tier drops that bar while the fine tier keeps
whatever minutes of it fall inside. It now aligns by open instant, drops the
first and last hour as genuinely partial, and requires every hour between them to
be identical field for field. An intermediate version skipped mismatched hours
instead, which would have made the assertion unfalsifiable.
