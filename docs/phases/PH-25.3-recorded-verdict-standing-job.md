## 1. Objective

Turn the instrument into an operation: a job that points at a running venue,
reads the longest served record the venue retains, runs the standing verdict
on it, and writes the verdict where the next reader finds it — and a first
verdict, recorded against the venue this session left running.

## 2. What is built

**`npm run assurance:served -- --base http://host:port [--asset id] [--out file]`**
in `tools/sim`. For each asset (all live ones by default): read `/markets/:id`
for the newest sequence, ask the stream for the retained window — the oldest
sequence is learned from the venue's own refusal, never guessed — and run
`servedAssurance` on what came back. The output is one Markdown record per run
with, per asset: ticks read, market time covered, outcome, hypotheses tested,
families built and withheld-unavailable, the detection floor per horizon, and
the worst z. An `exploitable` verdict exits non-zero, so a scheduler sees it.

**The record.** `docs/evidence/PH-25-SERVED-VERDICT.md`: the first run,
against the local venue on `:7300` hosting the catalogue of thirty, with the
floors it measured at the sizes the venue retained.

## 3. Acceptance criteria

1. The runner reads only the public surface; the boundary scan covers it.
2. The retained window is discovered from the venue's refusal, and a venue
   that refuses everything produces a named failure, not an empty verdict.
3. The evidence file exists and every number in it came from the run named
   in it.
4. An `exploitable` outcome is a non-zero exit; watched with the fake wire.

family's reference, so every asset after the first runs the full withheld
set (27 families); the first names `wh-cross-asset` as unavailable, honestly.

## 5. The first verdict — and the second, which names what it graded

_Cycle Audit 9 (a4-02) found the first run named no composition, build or
sequence range, and that the venue it graded was the **Lab composition**
(`lab.main.js` on `:7300`) on a build that predated PH-25.1's stream change.
The report carries all three now — the venue's boot nonce and whether
`/lab/markets` answers, the job's commit, and each asset's sequence range with
a SHA-256 of its ticks — and the recorded evidence file is the **second run**:
`apps/api/dist/main.js` composed for production on `:7402` at `5b3c154`,
thirty assets, seven minutes of record (462–2,000 ticks), every one
`undecided` with 0 hypotheses and 27 families (26 for the first asset, which
has no reference). The paragraph below describes the first run as it was, for
the record._

Against the venue this session left running on `:7300` — the Lab
composition hosting the catalogue of thirty plus one asset registered through
the panel — at 06:24 UTC: **31 assets, 0 exploitable, 0 failed, every one
`undecided`.** Every read was the
venue's whole retained window, which was about one hour on every asset
(3,610–13,334 ticks): the venue had been booted an hour earlier, and PH-25.1's
finding a says why nothing older is served. At default occupancy no bucket
reached 500 samples, so 0 hypotheses were tested and the floors say what an
hour can see: 21–31 pp at 30 s, 140 pp at 15 m. That is the honest state of
the instrument on a venue an hour old, recorded with its numbers rather than
rounded to a word. The job is the way to make it better: left running against
a venue that has run for days, the window is 50,000 ticks and the floors fall
with it; the record it cannot reach past a restart is PH-27.5's.
