## 1. Objective

Turn the instrument into an operation: a job that points at a running venue,
reads the longest served record the venue retains, runs the standing verdict
on it, and writes the verdict where the next reader finds it — and a first
verdict, recorded against the venue this session left running.

## 2. What is built

**`npm run assurance:served -- --base http://host:port [--asset id] [--out file]`**
in `tools/sim`. For each asset (all live ones by default): read `/markets/:id`
for the newest sequence, ask the stream for the retained window — the oldest
sequence is learned from the venue's own refusal, never guessed — and run
`servedAssurance` on what came back. The output is one Markdown record per run
with, per asset: ticks read, market time covered, outcome, hypotheses tested,
families built and withheld-unavailable, the detection floor per horizon, and
the worst z. An `exploitable` verdict exits non-zero, so a scheduler sees it.

**The record.** `docs/evidence/PH-25-SERVED-VERDICT.md`: the first run,
against the local venue on `:7300` hosting the catalogue of thirty, with the
floors it measured at the sizes the venue retained.

## 3. Acceptance criteria

1. The runner reads only the public surface; the boundary scan covers it.
2. The retained window is discovered from the venue's refusal, and a venue
   that refuses everything produces a named failure, not an empty verdict.
3. The evidence file exists and every number in it came from the run named
   in it.
4. An `exploitable` outcome is a non-zero exit; watched with the fake wire.
