# PH-16.1 — The Standing Verdict Runs the Battery It Names

Type: SUBPHASE TECHNICAL DOCUMENT
Identifier: PH-16.1
Parent: [PH-16](PH-16-close-what-the-audit-falsified.md)
Status: APPROVED

## 1. What was wrong

`assertIndependentFamilies` compared a list of **strings** against a constant. No
`AttackFamily` was constructed anywhere in the call graph, and the verdict was
derived from one statistic none of those families computes: the unconditional
up-rate per horizon.

An auditor built a record whose direction is the Thue–Morse parity of the hour —
fully predictable, every contract at every horizon won with certainty — and it
reported **`clean`**, because the up-rate is 0.5 by construction.

The module's docstring said the independence constraint was "made structural
here". What was enforced was that a caller typed four strings.

Separately, it computed its own detection floor from `designEffect`, which
measures between-block variance against a common-`p` null. Fixed heterogeneity
therefore read as dependence, and a record paying an observer +10.5% per trade
was reported `undecided` with a floor inflated 27-fold **by the leak's own
structure**. `dependence.ts`'s docstring forbids that use in as many words.

## 2. What it does now

It runs the battery. `runBatteryAsync` against a real observer dataset built
from the published record, and the detection floor is the battery's own
`minimumDetectableEffectPoints` — the instrument PH-11 built and validated for
exactly this. The hand-rolled floor is gone rather than repaired.

## 3. The correction that the measurement forced

The first version of this fix ran **only** the withheld families, reasoning that
independence from tuning was the point.

Measured, and wrong. On the clock-predictable record, with all four withheld
families available, the battery returned **88 hypotheses, zero exploitable, worst
z = −1.15**. Not one of the withheld families conditions on wall-clock phase; the
families that catch a clock-keyed leak — `second-of-minute`, `minute-of-hour`,
`horizon-grid-phase` — are in the main registry.

With the registry included, the same record returns **501 hypotheses, 97
exploitable findings, worst z = 77.6**, the largest a 48.89pp edge on
`previous-move` at 30 seconds.

So: the withheld families are what make the verdict **independent evidence**; the
registry is what gives it **coverage**. Running either alone produces a confident
answer to a question it did not ask. This was caught only because the fix was
probed rather than assumed.

## 4. Four outcomes' worth of honesty in three words

`clean` now requires all of: the battery clean, every horizon's floor finer than
the product margin, **and every withheld family constructible**. Four families
were withheld from tuning; a clean result from two of them is a weaker claim, and
reporting it under the same word would overstate it.

`exploitable` still wins at any power.

## 5. Verification

| Claim                                                           | How                                                                             |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| A clock-predictable record is reported `exploitable`            | full battery, all families available, asserts the alarm rather than "not clean" |
| The registry runs, not only the withheld families               | the verdict names registry families and is longer than the withheld set         |
| A family set missing a constructible withheld family is refused | on the family objects, not on names                                             |
| Each classifier rule fires on its own                           | `classifyStanding` tested directly                                              |
| A corrupted `lastRunAt` refuses rather than meaning "never due" | cadence battery                                                                 |

### Each guard watched failing

Eleven defects planted in turn. Six of them survived a first battery and are the
more interesting half.

| Planted defect                                              | Caught |
| ----------------------------------------------------------- | ------ |
| Only the withheld families, without the registry            | 1      |
| The independence check is removed                           | 3      |
| Exploitable findings are ignored                            | 1      |
| An unavailable withheld family no longer forces `undecided` | 1      |
| An insufficient floor no longer forces `undecided`          | 1      |
| No horizons at all reports `clean`                          | 1      |
| A battery that is not clean reports `clean`                 | 1      |
| The verdict reports the families asked for, not those run   | 1      |

The last five were **uncaught on the first attempt**, and all for one reason:
end to end the rules mask each other. A record short enough to lack power is also
short enough that nothing else fires, and `clean` needs more history than a unit
test can hold — so the composed function could only ever be observed saying
`undecided`. Every assertion about it was passing for a reason unrelated to what
it claimed.

`classifyStanding` is exported so each rule can fail for its own reason. That is
the same lesson as PH-15.3's design-effect plant, and it recurred in the fix for
it.
