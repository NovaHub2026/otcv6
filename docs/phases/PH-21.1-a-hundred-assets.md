# PH-21.1 — A Hundred Assets, And What Registering Them Costs

Type: SUBPHASE TECHNICAL DOCUMENT
Identifier: PH-21.1
Parent: [PH-21](PH-21-catalogue-at-scale.md)
Status: APPROVED
Created: 2026-09-02

---

## 1. Objective

Answer, with an executed run rather than an extrapolation, the first three of
the five questions PH-21 §1 lists: does a hundred-asset build succeed, do a
hundred assets stay distinct pair by pair, and what does each registration cost
— and whether any part of that cost grows with the size of the catalogue.

## 2. Scope

- `tools/sim/src/catalogueScale.ts` — a deliberate act, not a test: registers
  a hundred assets from the eight archetypes in rotation through the whole
  six-stage pipeline, each against everything already registered, and reports
  registration cost by archetype and the closest pair over every pair. Seeded
  by `OTC_SCALE_SEED`; reproducible. Recorded in
  [`CYCLE-7-CATALOGUE-SCALE.md`](../evidence/CYCLE-7-CATALOGUE-SCALE.md).
- `tools/sim/src/catalogueScale.stat.test.ts` — the properties that depend on
  the size of the catalogue, guarded on every gate at a scale the gate can
  afford: 200 drawn personalities every solve can author, 200 kept apart pair
  by pair, and one registration per archetype against a full catalogue.
- `packages/engine/src/brief.ts` — the brief runs the solve it will be
  registered with and retreats the drawn tail weight until it authors.
- `vitest.setup.statistical.ts` — an event-loop watchdog for the statistical
  suite, reporting the worst synchronous block per file.
- `packages/lab/src/differentiation.ts` — the non-held-out centroids computed
  once rather than inside the innermost loop.

**Excluded:** hosting a hundred markets (PH-21.2), and the panel (PH-21.3).

## 3. What the run found

**One brief in 400 was still unauthorable** — measured by a separate 400-brief
probe, not by the hundred-asset run, which refused none (the evidence document
records the distinction) — after the clamp Cycle Audit 6 added
for exactly this (CA6-24). All `alt-crypto`, all at the clamped ceiling:

```
guard-alt-crypto-20 authoring: An excess kurtosis of 141.19 needs more cascade
inflation than clustering 0.4 can provide at depth 5.
```

0.25% per draw is a **22% chance that a hundred-asset build stops on one**, and
the refusal the operator would see is about a personality they never chose.

The clamp could not have prevented it: `reachableExcessKurtosis` has no closed
form and is estimated by simulation (PH-10.1 §5.1), so 95% of a noisy estimate
is sometimes still too high. The only exact oracle for "can this personality
reach this tail weight" is the solve itself. `requestFromBrief` now runs it —
with the identical key derivation `registerAsset` will use, so a target that
authors in the brief authors in the registration — and steps the drawn target
down by a tenth until it succeeds, at most six times. It retreats only on the
solve's own `TailWeightUnreachableError`; any other refusal is rethrown after one
solve, because a lower target cannot fix it (out-of-band audit, a3-12).
`retreats` and the drawn target travel on the request's targets and on the
registered asset's `authored` record, so the catalogue says when a family asked
for more than the rhythm could supply (a3-05).

Measured after the change: **200 of 200 briefs authorable, one retreat, of one
step.** The retreat is a safety net, not a second sampler.

## 4. The instrument, again

Hosted CI is **red on `main`** on the three pushes since PH-19 merged, every
time with 238 statistical tests passing and one
`Error: [vitest-worker]: Timeout calling "onTaskUpdate"` — the failure this
project knows best (B-005, B-010, CA6-02, and the meta-audit fix in `c736707`
that was believed to be the last cause). PH-20 was approved with that run
pending, which is CA6-02 repeated: a phase approval without the corroborating
layer `GOVERNANCE.md` §40.1 requires.

Remembering the yield convention is not a guard, so the suite measures the
thing directly: a 250 ms timer in every statistical worker, and the gap between
when it should have fired and when it did. That gap is the block, whatever
caused it. It reports the worst block per file above two seconds and fails the
file above sixty, which is Vitest's own RPC timeout — a block that long means the
run's exit code has stopped describing the tests.

The first thing it caught was a test written in the same commit as the watchdog:
99.9 seconds of unbroken solving in `catalogueScale.stat.test.ts`, before the
yields between families. The second was the acceptance's own differentiation
classifier: `measureDifferentiation` recomputed every non-held-out centroid inside
its innermost loop, a factor of `windowsPerAsset` of identical arithmetic, and on
the sampled catalogue that was a 7.5-second synchronous block. The centroids are
computed once now, in the same order over the same values, so the sums are
bit-identical and no argmin can flip at a tie.

## 5. Acceptance criteria

1. `node tools/sim/dist/catalogueScale.js` registers 100 of 100 with zero
   refusals, and the closest pair over all 5,460 pairs clears
   `MINIMUM_TRAIT_DISTANCE` with stated headroom.
2. `catalogueScale.stat.test.ts` passes on the gate: no brief exhausts its
   retreats, the closest drawn pair clears the floor, and every archetype
   registers against the full catalogue.
3. No statistical file reports a worst block above the watchdog's failure
   threshold on a local run, and hosted CI is green on the same tree.

## 6. Approval

**APPROVED** 2026-09-02, from executed evidence, against the three criteria in §5.

1. **The hundred-asset build.** `docs/evidence/CYCLE-7-CATALOGUE-SCALE.md`:
   100 registered, 0 refused, 327 s in total, and the closest of 5,460 pairs at
   0.0282 — 2.8× the floor. Recorded before the out-of-band audit raised
   `alt-crypto`'s cascade depth (a3-05), and the evidence document says so; the
   properties the criterion is about are re-measured on every gate by
   `catalogueScale.stat.test.ts` at twice the catalogue size.
2. **The guard on the gate.** `tools/sim/src/catalogueScale.stat.test.ts` — 200
   briefs every solve can author, 200 personalities apart pair by pair, one
   registration per archetype against a full catalogue.
3. **The gate and its corroboration.** `npm run gate` exit 0 on `023f694`
   (unit 88 files / 2,165 tests; statistical 40 files / 265 tests), and hosted
   CI **green on the same tree** — run 33671271767, both jobs, the first green
   hosted run on a tree containing PH-19 and PH-20. `GOVERNANCE.md` §40.1 is
   satisfied for this subphase, which is more than the two phases before it
   could say when they were approved.

The watchdog this subphase added did not survive the audit unchanged, and that
is the honest part of the record: it could not see a block in a file's tail, so
a 65-second stretch reported nothing (a1-02). What replaced it measures the
round trip that actually fails the run and fails the file by name at thirty
seconds. The subphase's claim — that remembering a convention is not a guard —
was right; its first implementation of that claim was not.
