## 1. One shape, five times

Every finding in this subphase is the same shape: **a check that does not read
what it is cited as reading.**

| Finding | What it was cited as covering     | What it read                         |
| ------- | --------------------------------- | ------------------------------------ |
| CA6-01  | how the test suites run           | nothing — the file was in no program |
| CA6-03  | a comment, told from a string     | not a regular-expression literal     |
| CA6-11  | `apps/`, since Cycle Audit 4      | `packages/` only                     |
| CA6-12  | the browser bundle                | `.ts`, so two of nine files          |
| CA6-13  | comments, in the dependency guard | a private two-regex copy             |
| CA6-14  | every guardrail                   | never `singleWriter.test.ts`         |

Three of the six are the _second_ occurrence of a defect a previous audit
already found and a previous phase already recorded as fixed. CA5-05's
comment-marker evasion survives in `dependencies.test.ts` because PH-16.2 fixed
the shared scanner and left a private copy behind; CA5-11's observation that the
meta-audit never mutates `singleWriter.test.ts` was recorded and not acted on;
and `apps/` has been named in `guardrails.test.ts`'s own docstring as covered
since Cycle Audit 4 without ever being in the list.

**A guard is not what its docstring says it covers.** That sentence is the whole
subphase.

## 2. The one that reordered the cycle

`vitest.config.ts` was in no TypeScript program. The root `tsconfig.json` has
`"files": []` and ten references, none covering the repository root, and
`typecheck:web` covers only `apps/web`.

So `fileParallelism: false` and `maxWorkers: 8`, which Vitest 3 types as
`NonProjectOptions`, sat inside the _project_ blocks being silently ignored. The
statistical suite had never run serially. The tell was in every summary:
`detectionPower` alone reporting 707 seconds of test time inside a 749-second run
that also ran everything else.

Two consequences that had been read as something else for a whole cycle:

- **`Timeout calling "onTaskUpdate"`** — the failure this repository knows best,
  attributed until now to long synchronous test bodies. Those were real and
  fixed, and the standing cause was the statistical files oversubscribing the box
  against each other.
- **Every wall-clock assertion in the statistical suite was measuring
  contention.** Four throughput floors, one of which had already been lowered
  once in PH-18 for what looked like a slow machine.

Concurrency now sits at the root. The gate runs the two projects as separate
invocations, which is the only place per-project concurrency can be expressed and
what CI has always done. `tsconfig.config.json` puts the file in a program and
`npm run typecheck:config` runs in the gate and in CI.

The honest cost is a **20-minute gate instead of a 5-minute one that was lying**.

## 3. Refusing to read a coarser thing than asked

`moduleSpecifiers` replaces the dependency guard's regular expression, because a
pattern cannot tell apart the two strings that matter: a specifier is a string,
and a test fixture _describing_ an import is also a string. Sharing the correct
comment scanner immediately surfaced that second half — `singleWriter.test.ts`
holds `"import * as engineModule from '@otc/engine';"` as a fixture, and the old
pattern read it as an import. A guardrail failing on another guardrail's evidence
is the same class of defect as a guardrail passing on a real one.

## 4. Every guard watched failing

| Planted defect                                                 | Caught by                 |
| -------------------------------------------------------------- | ------------------------- |
| A regex literal hiding a static engine import in `follower.ts` | `singleWriter.test.ts`    |
| `import '@otc/fixtures'` in a `.tsx` component                 | `dependencies.test.ts`    |
| The CA5-05 comment-marker evasion in a `.ts` file              | `dependencies.test.ts`    |
| An ambient economic channel in `apps/api/src/venue.service.ts` | `guardrails.test.ts`      |
| Both of the first two, re-run through the meta-audit           | `guardrailMetaAudit.stat` |

The meta-audit's table grew by two: the follower guard PH-16.2 rewrote, and a
`.tsx` file. Both were absent for the same reason — the table only ever named
files under `packages/`.

## 5. Coverage

`apps/*` is measured now. It was defensible while the apps were thin wiring and
stopped being so in PH-18: 840 lines of `apps/api/src` are directly unit-tested
and were simply not counted, and not one line of `apps/web/src` is referenced by
any test at all. A coverage figure that excludes the code you are least sure
about is the wrong way round.
