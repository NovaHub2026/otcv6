## 1. What registration has to do

Five stages, in this order, any of which may refuse and each naming itself when
it does — because "the asset was rejected" is not actionable and "the personality
solve could not reach that tail weight from this ladder" is.

| Stage             | Refuses                                                                                               |
| ----------------- | ----------------------------------------------------------------------------------------------------- |
| `identity`        | an id that cannot be a filename or a key label, a duplicate, an unusable reference price or precision |
| `safety`          | a personality whose layers compound past the realism ceiling, in microseconds                         |
| `authoring`       | targets the solve cannot reach from the given ladder                                                  |
| `calibration`     | a lattice that cannot be derived from this asset's own returns                                        |
| `differentiation` | an asset indistinguishable from one already registered                                                |

The gate runs before the solve deliberately: it costs microseconds and the solve
costs a minute.

## 2. The traits that get registered are the solved ones

`authorPersonality` solves `volatility` and `clustering` from targets. What the
caller supplies is a starting point; what the catalogue records is what the solve
achieved, measured against the stream that drove it.

Registering the request instead would publish a personality nothing computed —
the number and the market would disagree, and only the number would be visible.
PH-10.1 already made this point about targets versus achievements; this is the
same point at registration time.

## 3. Why the differentiation check is injected

It needs `@otc/lab`, and the dependency direction forbids the engine from
reaching it — correctly, because lab carries the planted-defect corpus and
nothing in the venue may drag it in.

So the engine states the requirement and the caller supplies the implementation.
Deliberately **not** an optional parameter with a permissive default: a
registration with no differentiation check would let a hundred assets be twenty
clones of five, and INV-007 would be false the moment the catalogue grew.

## 4. Each guard watched failing

Six defects planted. Three were uncaught on the first attempt, and all three for
the same reason — the assertions did not discriminate:

| Planted defect                                           | First run | After |
| -------------------------------------------------------- | --------- | ----- |
| The identity check is skipped                            | 1         | 1     |
| A duplicate id is admitted                               | 1         | 1     |
| The differentiation result is ignored                    | 1         | 1     |
| The safety gate does not run                             | **0**     | 2     |
| The request's traits are registered, not the solved ones | **0**     | 1     |
| The lattice is supplied by the caller                    | **0**     | 2     |

- The unsafe-personality test accepted a refusal at `safety` **or** `authoring`.
  With the gate skipped the solve refused anyway, so the test could not tell
  which guard had fired. It now uses a personality whose traits are each in range
  and which compounds to an excess kurtosis of ~14,900 against a ceiling of 200,
  and asserts the stage exactly.
- The solved-traits test only checked that the recorded kurtosis was positive. It
  now asserts the registered `clustering` differs from the requested one.
- The lattice test checked `logQuantum > 0`. It now asserts the instrument
  publishes the same number the calibration derived — they are the same quantum
  or the lattice that settles is not the one that was measured.
