## 1. Objective

Turn the assurance verdict from something an operator runs into something the
venue produces, against its own accumulated history, with a floor that is honest
on the first day and on the thousandth.

## 2. What "standing" has never been

PH-9 made the verdict re-derivable from the published record with no key. PH-11
gave it detection power at every horizon the product sells. Both are capabilities.
Neither runs.

The gap between "we verified this in August" and "this is verified" is the whole
of what a counterparty is buying, and a guarantee that requires someone to
remember to run something is a claim about the past.

## 3. The floor is an output, and this is the hard part

A battery run against accumulated _real_ history is a different statistical
object from one run against a simulation. A simulated run chooses its duration;
real history arrives at one tick per tick.

PH-11's central finding is that every statistic here is limited by **elapsed
duration, not sample count** — the volatility process has memory measured in
days, so consecutive observations are never independent draws, and the design
effect is real and large.

So the detection floor **moves as history accumulates**. A standing report
quoting a fixed floor is wrong in one direction on its first day and the other
on its hundredth. It is recomputed every run, from the history actually held,
and stated with the verdict.

## 4. Three verdicts, not two

A young venue has almost no power. Reporting `clean` from it would be the single
most misleading thing this system could say: it would be indistinguishable from
the same word after a year, and it is the word a counterparty acts on.

So a horizon whose recomputed floor is **coarser than the margin the payout
implies** returns `undecided`. Not clean, not exploitable — the measurement
cannot see an edge that would matter, and saying so is the honest report.

| Verdict       | Meaning                                                           |
| ------------- | ----------------------------------------------------------------- |
| `clean`       | The floor is finer than the product margin, and no edge was found |
| `exploitable` | An edge exceeding the floor was found                             |
| `undecided`   | The floor is coarser than the product margin: not yet measurable  |

`exploitable` is reported at any power. An edge large enough to clear a coarse
floor is a finding whether or not the sample could have seen a smaller one.

## 5. Monitoring, not a tuning loop

PH-9.1 withheld four attack families from every tuning decision, and said why:
"their value is entirely that no engine decision has been made with them in
view, which means it can be destroyed by using them that way."

A battery that runs continuously against live history, whose failures prompt
engine changes, is exactly that destruction — reached by a route that looks like
diligence. The standing run is monitoring: its results are recorded, a failure is
an incident, and no engine parameter changes because of it.

That is a constraint on operations, which is the kind that erodes silently. So it
is made structural in the one way available: **the standing run refuses to
produce a verdict from a family set that omits any withheld family.** A verdict
built only from the families the engine was shaped to survive is not independent
evidence, and the runner will not sign its name to one.

## 6. What is built

`packages/lab/src/standing.ts`

- `StandingVerdict`, `HorizonStanding` — the report, with the floor in it.
- `assessStanding` — recomputes the floor per horizon from the history given.
- `assertIndependentFamilies` — the refusal in §5.
- `isStandingRunDue` — the cadence, with an injected instant.

## 7. Verification

| Claim                                                                 | How              |
| --------------------------------------------------------------------- | ---------------- |
| The floor is recomputed, not read from a constant                     | standing battery |
| More history gives a finer floor                                      | standing battery |
| A short history returns `undecided`, never `clean`                    | standing battery |

## 8. Out of scope

Alerting, dashboards, on-call, and who reads the verdict. The run records it;
what an operator does next has no code in this repository.

### A test that could not see its own subject

"Dependence is assumed rather than measured" — replacing the measured design
effect with a hard `1` — passed the first battery. The reason is worth
recording: every record the battery generated was an **independent fair coin**,
whose true design effect _is_ 1. The test asserting the measurement was
therefore asserting that 1 equals 1, on data where nothing else was possible.

A generator with real block-level heterogeneity was added — alternating drift, so
each replicate block has its own up-rate — and the plant now fails. The same
record also demonstrates the consequence that matters: **the same amount of
history buys a coarser floor when the observations are dependent**, which is
PH-11's finding restated by the measurement rather than asserted alongside it.

This is the second time in this phase that a plant surviving meant the test's
_data_ could not express the defect, not that a check was missing.

### The decisions recorded here

**Three verdicts, not two.** A horizon whose recomputed floor is coarser than the
0.2513pp product margin reports `undecided`. Reporting `clean` from a record with
no power would be the most misleading thing this system could say: it is
indistinguishable from the same word after a year, and it is the word a
counterparty acts on. `exploitable` is reported at any power, because an edge
clearing a coarse floor is a finding regardless.

**The standing run is monitoring, and refuses to be anything else.** It will not
produce a verdict from a family set that omits any withheld family. PH-9.1's
withheld families are worth exactly their independence from tuning, and a
standing verdict built only from the families the engine was shaped to survive
is not evidence. The constraint is on operations, which is the kind that erodes
silently — so the runner enforces it rather than documenting it.

**The cadence is daily**, and takes its instant from the caller. The quantity
being measured moves on a timescale of days, so running more often would
re-measure the same dependence and report a floor that had not changed.
