## 1. What was wrong

PH-14.2 claimed a follower is **structurally unable** to generate, and PH-14 §12
cited `singleWriter.test.ts` as the evidence for INV-002 and INV-010.

An auditor defeated it four ways and then used one to build the thing the guard
exists to prevent: a `FollowerMarket` with a real engine behind `fillGap()`.
Sampled over the window both sides covered, leader and follower **disagreed at
120 of 120 instants**, first divergence 210 lattice steps.

| Evasion                                                     | Why the guard missed it                                                  |
| ----------------------------------------------------------- | ------------------------------------------------------------------------ |
| `const OPEN = '/*'` around a plain static import            | the comment stripper was two regexes and knew nothing of string literals |
| `await import(\`./resume.js\`)`                             | `specifiers()` matched only `['"]`                                       |
| `await import(['.', 'resume.js'].join('/'))`                | no name-based scan can see an assembled specifier                        |
| `RandomStream`, `expandKey`, `CursorLease` from `@otc/core` | `@otc/core` is a permitted dependency and only `MasterKeyring` was named |

## 2. Chasing names was the mistake

Three of the four evasions were not about _which_ module was reached. They were
about reaching it in a form no list of names can see. Adding each name would have
caught none of them.

So the rule is now about the **construct**. A module that must be provably unable
to reach the engine may contain no dynamic escape hatch at all — no `import(`,
`require(`, `createRequire`, `Function(`, `eval(`, or `globalThis`. There is no
legitimate use for one in a module whose whole job is to replay a record it was
handed, and banning the category closes the class rather than the instance.

The comment stripper is now `stripCommentsKeepingStrings`, a character scanner
that knows a string from a comment that looks like one. It lives in
`sourceScan.ts` beside the lexer that already did this correctly for the other
guards — the follower guard had rolled its own.

## 3. The settlement half

PH-14.3 built `spansSeam` with the docstring _"the settlement path needs to be
able to ask"_. Nothing asked: `settle` used `priceAtOrBefore` with no seam
awareness at all.

Worse, `spansSeam` required the window to **contain** the seam, so a contract
with one endpoint inside the gap was reported clean — while `priceAt` refused to
answer for that same instant. The two contradicted each other and the permissive
one was the one the settlement path is told to consult.

An auditor produced a real 93-second failover gap and a contract whose expiry
landed inside it: `priceAt` returned null, `spansSeam` said clean, and the
contract settled as a loss against the last pre-seam tick.

Both are fixed. `spansSeam` tests **overlap**, and `TickRecord` carries optional
seams that `settle` refuses to settle across — ADR-0010's rule applied to a read.
The field is optional, so a record with no seams behaves exactly as before.
