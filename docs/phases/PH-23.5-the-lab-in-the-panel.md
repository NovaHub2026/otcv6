## 1. Objective

Close the first item in PH-23 §10: **"No UI. Every subphase built API and
boundary; §5–§7's screen is not built."**

The Human Owner named it directly — _"donde está diseñado el lab en el front,
debería estar en el panel también como un menú, no solo en el back"_ — and the
phase document had already conceded the point. The API was reachable only by
`curl`, which is not what §5–§7 of the specification describe.

## 2. Scope

- `apps/web/src/app/lab/[...path]/route.ts` — a proxy that points at
  `OTC_LAB_BASE` and, when unset, answers 503 with how to start a Lab.
- `apps/web/src/app/lab/Lab.tsx`, `page.tsx` — the screen.
- `apps/web/src/app/Nav.tsx` — the menu entry, marked `SIM`.
- `apps/api/src/lab/lab.controller.ts` — a `markets` route, a rendered price,
  and the two verdict corrections §4 and §5 describe.
- `apps/web/src/labScreen.test.ts`, `apps/api/src/lab/labMarkets.test.ts`,
  `apps/api/src/lab/labQuality.stat.test.ts` — the guards.
- `~/.otc-local/start.sh` — a local artefact, not a repository one: it starts a
  Lab on its own port and its own state directory.

**Excluded:** interventions on the screen (PH-23 §10, still open), §67's jobs,
and §74–§77's replay surface.

## 3. The boundary is the panel's shape, not a check inside it

Three decisions carry ADR-0015 §3 into the front end, and each is a property
rather than a rule someone has to remember.

**The proxy points at `OTC_LAB_BASE`, never at the engine.** If it pointed at
the engine with a different prefix, the panel would make Lab routes reachable
from a service that does not have them, and the composition boundary would end
at the browser. With `OTC_LAB_BASE` unset there is nothing to reach, and the
screen says so — absence by default on both sides.

**The screen lists the Lab's own markets.** It asks the Lab which markets _it_
hosts, so a production asset id never reaches it. §3 says Lab controls must
never be available for manipulating a live market carrying positions; a screen
that listed production's catalogue beside a close-selection control would be
offering exactly that, whatever the request underneath actually reached. A check
on the way out would have been a flag, and this project has an ADR about what
flags are worth.

**Run locally, the Lab gets its own state directory.** Pointing it at the
service's would put two writers on one store, against ADR-0012, and would make
the Lab's markets the same markets the panel trades. The launcher's line reads
`state ~/.otc-local/lab-state`, and the panel's header shows the engine hosting
six markets while the Lab lists five — the separation, visible.

## 4. The verdict the panel printed, and what was behind it

The first working screen reported **`predictability: clean`**. It was true and
it was worthless, and the measurement is the reason:

|     ticks | hypotheses tested | seconds |
| --------: | ----------------: | ------: |
|    40,000 |                 2 |     1.4 |
|   200,000 |                92 |     7.0 |
| 1,000,000 |               378 |     5.7 |
| 2,000,000 |               575 |     7.3 |

The battery drops any bucket holding fewer than 500 decided outcomes. At the
40,000 ticks this route sampled, **two** hypotheses survived out of the eight
hundred it defines — and two reads exactly like 378 when the word on the screen
is the same. This is CA7-05's failure a second time, in a panel written by the
agent that had just recorded CA7-05.

Three things changed:

1. **The default sample is a million ticks**, which is where the recorded
   evidence's own floor sits (`report.stat.test.ts` asserts above 300), and it
   costs six seconds.
2. **The verdict has three outcomes, none of them the bare word.**
   `inconclusive` below a hundred surviving hypotheses — that is not a weaker
   clean, it is no verdict; `exploitable` when an attack lands; otherwise
   `clean-above-resolution`, printed beside the resolution it holds at. The
   panel reads **"no edge above 6.01pp"**, against a 0.25pp materiality
   threshold, which is the honest shape of what a bounded run establishes.
3. **The battery's own `notes` are rendered.** Four sentences saying how many
   buckets went untested and that a clean verdict at these horizons means "no
   edge above the stated resolution". They were being computed and dropped.

## 5. Realism had the same defect, and only measurement found it

The screen also printed **`14 of 15 — IMPLAUSIBLE`**, failing
`aggregational-gaussianity`. Three consecutive forks of the same EUR/USD market
at the same sample size then measured **14/15, 15/15, 15/15**.

So a bounded run's realism verdict flips between runs while the market does not,
and printing `IMPLAUSIBLE` from one of them is the same error as printing
`clean` off two hypotheses: a claim the sample cannot support, in a word that
reads like one it can. The screen now says **"15 of 15 metrics inside their
bands, on this fork"** with a note naming the measurement, and the word
`IMPLAUSIBLE` is guarded against returning.

Neither defect was visible by reading. Both came from running the thing and
asking what the number rested on.

## 6. A third: a lattice index under the word "price"

`snapshot.price` is the integer log-lattice level (ADR-0004). For EUR/USD it
reads `-12294` while the market shows `1.08`, and the screen labelled it
`price`. On the screen where an operator decides whether a close is reachable,
those two must not be confused. The route returns both, named for what each is.

## 7. Acceptance criteria

1. The Lab is reachable from the panel's menu, marked as a simulation.
   **Met** — `Lab · SIM`, a red rule where the others are green, verified in
   Chromium: `NAV: "OTC ENGINE Preview Create asset Assets Lab SIM engine ok · 6 hosted"`.
2. `OTC LAB` and `SIMULATION ENVIRONMENT` are permanently displayed (§3).
   **Met** — in the frame, above the scrolling area, asserted by
   `labScreen.test.ts` and watched failing against a banner moved inside the
   scroll container.
3. The screen cannot name a production asset. **Met** — it lists the Lab's own
   markets; watched failing against a plant that restores `fetchCatalogue`, and
   against one that hands the page an engine base URL.
4. No verdict is printed without what it was measured on. **Met** — §4 and §5;
   watched failing against both restored ternaries and against the note losing
   its handle.
5. The three sections work end to end in a real browser. **Met** — state
   refreshing at 2 s with the price at `1.0814049` and the lattice level at
   `-12064`; reachability `normal` at +12 steps with 965 attempts and an
   acceptance rate of 0.001036, and `outside-natural-range` at +999,999 refused
   by arithmetic with **zero** attempts and its reason named; quality returning
   376 hypotheses in 5.1 s. No console errors on any pass.

## 8. Approval

**APPROVED** 2026-09-03, from the executed runs quoted above and a full
`npm run gate` on this tree: `GATE_EXIT=0` — unit 102 files, 2,347 tests;
statistical 41 files, 268 passed and **8 skipped**. The eight are the browser
suite, which skips by name wherever Chromium cannot load its libraries, and the
gate ran without the prefix. Run separately with
`LD_LIBRARY_PATH=~/.otc-local/browser-prefix/usr/lib/x86_64-linux-gnu`, the
suite executed: **8 of 8 in 41.7 s**. Both runs are the approval; a gate that
skipped the browser on a subphase whose deliverable is a screen would not have
been one.

The first gate run failed three documentation guards — the roadmap did not list
this subphase, so the subphase document, the roadmap and `CURRENT_STATE.md` were
not three documents in agreement. Corrected, and the guards were the reason it
was noticed.

Plants watched failing, each restored and re-run green:

| plant                                                | guard                |
| ---------------------------------------------------- | -------------------- |
| banner moved inside the scrolling container          | `labScreen.test.ts`  |
| the quality caveat loses its handle                  | `labScreen.test.ts`  |
| the screen reads the production catalogue            | `labScreen.test.ts`  |
| the page hands the screen an engine base URL         | `labScreen.test.ts`  |
| the bare `clean` / `EDGE DETECTED` ternary returns   | `labScreen.test.ts`  |
| the bare `plausible` / `IMPLAUSIBLE` ternary returns | `labScreen.test.ts`  |
| the realism note loses its handle                    | `labScreen.test.ts`  |
| `markets` returns the catalogue, hosted or not       | `labMarkets.test.ts` |
| `session.ts` offers a merged timeline                | `labSession.test.ts` |

Two of those guards were themselves defective when first written and are worth
recording. One extracted the panel with a regex ending at the first `\n}`, which
is the closing brace of a destructured parameter list — it matched nothing and
passed. The other fired on the docstring saying the screen is not given an
`apiBase`. Every "this file must not contain X" assertion now runs on
comment-stripped source, because the place X is likeliest to appear is the
comment explaining why it must not — which has now cost this project four
guards.
