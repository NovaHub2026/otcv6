## 1. Objective

Cycle Audit 9 handed forward that seventeen of thirty assets are measured by
no heavy suite at any gate. The release records every one of the thirty
measured on the build that ships: the standing verdict from the served record
over a run long enough to decide something, and the conformance suite, both
against the release build in production composition.

## 2. What is run

1. Boot the release build on the thirty with a record and publication on;
   run for an hour of market time.
2. `npm run assurance:served` against it: thirty records from sequence 1,
   the standing verdict per asset with both floors.
3. `npm run conformance` against it.
4. The two records are copied into `docs/evidence/` as the release's
   evidence and indexed; the per-asset table names, for each of the thirty,
   the verdict, the floors and the digest of the ticks read.

## 3. Acceptance criteria

1. Thirty of thirty graded, none `exploitable`, every row with its digest.
2. The conformance suite passes the release build.
3. Both records name the commit they measured.

## 5. What the subphase found

- **A deploy-length restart made the durable venue serve nothing, and the boot
  after it died (fixed, `1` guard each).** The first hour's venue was stopped
  cleanly and restarted 23 minutes later on the same directory; every market
  seamed, as it does after any restart past the 15 s catch-up bound. The feed,
  primed with the record's pre-seam tail (PH-28.1), refused the first post-seam
  tick as a gap — and every one after it, for every asset, while the record
  filled: the standing job read thirty 400s. A prompt third boot died priming
  the chain across the recorded jump. And the chain restart PH-28.3 promised
  produced a file the project's own verifier refused. Now a seamed market's
  feed begins at the seam, the chain restarts at the seam and at any jump the
  record holds, and `verifyCommitmentsFile` names each restart in `breaks`
  (`DECISION-LOG.md`, 2026-09-06). Guards: the three-boot test in
  `venueRecord.test.ts` and the two-chain test in `commitmentsFile.test.ts`,
  both watched failing first. The hour on the release build is being re-run on
  the fixed build with a deploy-length restart in the middle, because that is
  the run a broker's venue has.
