# PH-28.2 — The Venue's Handle: Production Controllers See A Published View, Never The Engine

Type: SUBPHASE TECHNICAL DOCUMENT
Identifier: PH-28.2
Parent: [PH-28](PH-28-durable-venue.md)
Status: APPROVED
Approved: 2026-09-05 — from the evidence in §6
Created: 2026-09-05

---

## 1. Objective

Close what Cycle Audit 9 handed forward (a1-01): `VenueService`, injected into
every production controller, exposes `hostedMarket()` and with it
`snapshotEngine()` — every keystream cursor and the latent state. The by-value
guard on production responses closes the leak at the wire; this subphase
closes it at the type, so that no production source can name the engine
because no object it holds can reach one.

## 2. What is built

**`EngineAccess`** (`apps/api/src/engineAccess.ts`): the engine-touching
surface moved out of `VenueService` — `hostedMarket`, `labFork`,
`labTicksAhead`, `labTicksAheadAsync`, `labStepsAhead`, `labRandom`. It is
constructed inside `VenueService` and handed out **once, through a callback
the composition passes** (`AppModuleOptions.engineAccess`), the way the sign
source is: `main.ts` registers the application bare, so in production the
object is never created; `LabModule` passes the callback and provides what it
receives to the Lab's controller, observer and footprint. ADR-0015 §3 again:
the boundary is what is composed, not a flag.

**The guard** (`labSurface.test.ts`): `VenueService` declares no method that
returns a `HostedMarket`, an engine snapshot or a fork; `snapshotEngine` is
named under `apps/api/src` only in `engineAccess.ts` and under `lab/`;
`EngineAccess` is constructed only in `venue.service.ts`; `app.module.ts`
declares and passes the option and does nothing else with it. Each watched
failing against a plant.

## 3. Acceptance criteria

1. `VenueService`'s public surface has no path to a `HostedMarket`, a snapshot
   or a fork; the type says so and the guard checks the source.
2. The Lab works unchanged through `EngineAccess`: every Lab test green.
3. `main.ts` and `app.module.ts` are bare; `composition.test.ts` asserts the
   option is declared and passed and nothing more.
4. The production-responses guard (a1-01) still passes, and a planted route
   cannot reach a snapshot without an import from `lab/`.
5. Every guard watched failing.

## 5. What the subphase found

1. **A callback, not a branded token** — the decision log has the reasoning:
   an unwrap method on the venue's type is still a method on the type.
2. **The word count is not the boundary.** The composition guard counts the
   option's mentions in `app.module.ts` the way it counts the sign source's;
   the import path `./engineAccess.js` is a mention the regex had to exclude,
   and `options.engineAccess` one it had to keep.
3. **The venue's own docstring tripped the guard** by naming the moved
   methods; it names them by kind now. A guard that reads source reads
   comments too, which is what makes it hard to get past and easy to trip.
