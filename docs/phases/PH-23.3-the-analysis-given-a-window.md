## 1. Objective

Serve, over the Lab's isolated surface, the analysis this repository has been
running headless for eight phases.

Sections §52–§68 of the specification describe a laboratory. `packages/lab` **is
that laboratory**. What it has never had is a window.

## 2. What exists, against what was asked for

| Specification                                             | What answers it                                                          |
| --------------------------------------------------------- | ------------------------------------------------------------------------ |
| §52 session statistics, green/red split                   | realism metrics over the observer dataset                                |
| §53 streak analysis                                       | directional run-length statistics                                        |
| §54–§55 trend and sideways analysis                       | regime metrics and volatility-regime range                               |
| §56 candle structure, uniformity detection                | displacement heterogeneity, body/range metrics                           |
| §57 return distribution, skew, kurtosis                   | excess kurtosis, aggregational gaussianity                               |
| §58 autocorrelation                                       | absolute-return autocorrelation at lag 1, long memory                    |
| §59 regime transitions                                    | volatility-clustering dominance, regime range                            |
| §60–§62 predictability, baseline and indicator strategies | the attack battery: ~800 hypotheses across four feature families         |
| §63–§65 configuration, results, edge detection            | the battery's verdict, with Benjamini–Hochberg and held-out confirmation |
| §66 expiration coverage                                   | horizon tally, every expiration 30 s to 15 m                             |
| §67 large simulations                                     | `tools/sim`, 24M-tick runs                                               |
| §68 market quality dashboard                              | the realism verdict (15 metrics with bands) plus the battery verdict     |

**The specification's strategy list is a subset of the battery**, with one
difference that decides whether any of it is worth acting on: the battery states
the resolution at which it found nothing. "Clean" and "clean at a minimum
detectable effect of 0.22pp" are different claims (`VALIDATION.md`), and only
the second can be believed.

## 3. What this subphase must not do

**It must not restate a verdict without its sensitivity.** A dashboard that
shows `Predictability Resistance 96/100` and hides the MDE is worse than no
dashboard: it invites exactly the reliance `differentiation.ts` warns about and
that Cycle Audit 7 caught PH-21 committing (CA7-05).

**It must not ship the battery to the browser.** `@otc/web` may never depend on
`@otc/lab` or `@otc/fixtures` (ADR-0015 §1). The analysis runs on the server;
the browser receives results.

**It must not run a twenty-four-million-tick battery inside an HTTP request.**
Large runs are jobs with a record, like registration (§67).

## 4. Acceptance criteria

1. The Lab serves the realism verdict — all fifteen metrics, each with its
   value, its band and whether it passed — for a live asset.
2. The Lab serves the battery verdict for an asset, **with its minimum
   detectable effect beside it**, and a guard asserts the two are never
   separable.
3. Every number served is the same number the gate computes, verified by
   comparing against the same function rather than reimplementing it.
4. `@otc/web` still cannot reach `@otc/lab`, asserted after the change.
5. A large run is a job with an id and a record, not a request that blocks.
